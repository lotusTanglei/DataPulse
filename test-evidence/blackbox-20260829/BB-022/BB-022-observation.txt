BB-022 从数据源创建数据集闭环观察
执行日期：2026-08-31
执行环境：前端 http://127.0.0.1:5173；后端 http://127.0.0.1:8001；隔离测试数据目录 /tmp/datapulse-blackbox-20260831
账号：专用测试管理员（不记录密码）

操作与实际观察：
1. 从“数据集”页面点击“从数据源创建”，路由进入 /studio/datasources。
2. 打开测试数据源 erp（MySQL/MariaDB），详情页加载完成，最终 URL 为 /studio/datasources/cce8c077-1769-488d-ae9e-7c2b586d7b73。
3. 直接核对接口：GET 数据源详情返回 200；namespaces 返回 200；relations 返回 200。
4. 进入“SQL 调试”，执行 SELECT 1 AS health_check，查询接口返回 200，页面显示 1 行并出现“保存为数据集”。
5. 保存临时数据集 BB-022-1788144057577，POST /api/admin/datasets 返回 201，页面跳转 /studio/datasets/9c900d1b-d0a4-4b5e-9b9c-d9e74f21fece；GET 数据集详情返回 200。
6. 使用真实 ERP 表执行 SELECT * FROM products LIMIT 5，查询返回 200（5 行）；保存临时数据集 BB-022-products-1788144146603，POST 返回 201，并跳转数据集详情。
7. 只读核对中文字段编码：查询 `product_name`、`HEX(product_name)` 及连接字符集，API 返回的连接字符集均为 `utf8mb4`，但数据库原始字节已是乱码字符串的 UTF-8 编码（双重编码形态）。这属于当前 ERP 测试数据源的内容质量异常，尚不能归因于 DataPulse 产品实现。

清理：上述两个临时数据集 DELETE 均返回 204；清理后数据集列表中 BB-022-* 数量为 0。

结论（仅为本次观察，不作为整体发布结论）：正确的“数据集 → 从数据源创建 → 数据源 → SQL 调试 → 保存为数据集”路径可完成创建；本次未复现“无法从数据源创建数据集”。用户随后确认此前是找错入口。ERP 测试数据存在待数据源所有者确认的中文编码异常，已单独记录为外部数据质量风险。截图：BB-022-detail-loaded.png、BB-022-save-result.png、BB-022-products-save.png。

备注：一次自动化脚本使用了未转义点号的 CSS 选择器而在浏览器脚本层报错，该错误属于测试脚本定位问题，未产生产品请求，不计为产品缺陷。
