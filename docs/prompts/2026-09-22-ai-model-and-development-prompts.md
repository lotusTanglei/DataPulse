# DataPulse AI 模型选型与开发提示词

日期：2026-09-22
相关：`../superpowers/plans/三阶段计划.md` · `../superpowers/plans/开发顺序.md`

本文分两部分：**模型选型**（驱动项目开发用哪个模型）和**开发提示词**（可直接复制给 AI 编码代理执行）。

## 一、模型选型

### 1.1 结论

| 用途 | 推荐型号 | API 型号 ID | 说明 |
| --- | --- | --- | --- |
| 主力开发（推荐） | GPT-6 Astra | `gpt-6-astra` | 官方称为「至今最好的软件工程模型」，长上下文和结构化输出最强 |
| 高配额开发 | GPT-6 Astra Pro | 以控制台为准 | Pro / Business / Enterprise 可用 |
| 备选（成本优先） | GPT-5.6 Sol | 以控制台为准 | 上一代前沿，能力仍强，价格更低 |
| 轻量任务 | GPT-5.6 Terra / Luna / GPT-5 Thinking Mini | 以控制台为准 | 适合局部修改、话术生成等简单任务 |

### 1.2 为什么选 GPT-6 Astra

与 DataPulse 的需求直接对应：

| 需求 | Astra 的表现 |
| --- | --- |
| 软件工程能力 | Terminal-Bench 4.0 57.9%（GPT-5.6 Sol 37.3%） |
| 长上下文（多数据集画像） | MRCR 256K-512K 100%，512K-1M 96.3% |
| 代码质量 | FrontierCode 1.1 Main 53.3%，DeepSWE 74.1% |
| 遵循模板与既有约定 | 官方明确强调擅长「adhere to existing templates」和结构化产出 |
| Agentic 编码效率 | Codex 下任务完成速度比 GPT-5.6 Sol 快 1.9 倍（Mind2Web） |
| 边界遵守 | 越界率 0%（GPT-5.6 Sol 48%），这对「不许自动发布」的约束很重要 |

### 1.3 API 与价格

- API 型号：`gpt-6-astra`
- 价格：**$10 / 百万输入 token，$50 / 百万输出 token**
- Fast 模式：速度最高 2 倍，价格也是 2 倍
- 可用渠道：OpenAI API、ChatGPT Plus / Pro / Business / Enterprise、Microsoft Azure、AWS Bedrock

### 1.4 两个必须注意的点

**第一：Enterprise 默认关闭。**

官方说明 Enterprise 管理员需手动为工作区启用 Astra，**默认是关的**。团队要用先去管理台打开。

**第二：DataPulse 会把数据发给模型，必须确认合规。**

`ai/context.py` 会把数据集名称、字段结构、最多 100 行样例发给模型。使用前必须确认数据分类、脱敏、跨境传输和供应商留存策略。Astra 支持符合条件客户的 Zero Data Retention，如有合规要求应申请。

### 1.5 应用内 AI 功能怎么配

DataPulse 本身是模型无关的（OpenAI-compatible `/chat/completions`），`DATAPULSE_AI_MODEL` 运行时填写：

```bash
DATAPULSE_AI_ENABLED=true
DATAPULSE_AI_BASE_URL=https://api.openai.com/v1
DATAPULSE_AI_MODEL=gpt-6-astra
DATAPULSE_AI_API_KEY=...
DATAPULSE_AI_TIMEOUT_SECONDS=120   # 整屏生成建议提到 120
```

建议分档：整屏生成用 `gpt-6-astra`，局部修改和话术生成用较轻模型。

### 1.6 核查说明

- 以上型号名来自 OpenAI 官方页面（2026-09-22 抓取）：GPT-6 Astra 发布页与 Business 定价页的模型列表（GPT-5.6 Sol / Sol Pro / Terra / Luna / GPT-5 Thinking Mini）。
- `platform.openai.com/docs/models` 与 `developers.openai.com/api/docs/models` 返回 403，`api.openai.com/v1/models` 连接超时。
- 因此**除 `gpt-6-astra` 外的 API 型号 ID 未逐一核实**，请在控制台或 `/models` 接口确认后再写入配置。

## 二、开发提示词

### 2.1 使用方式

1. 三阶段计划和开发顺序已经放在 `docs/superpowers/plans/` 下，直接使用仓库内版本。
2. 每轮**只让 AI 做一个批次**，不要一次给全部阶段。
3. 每轮结束时要求它跑 `pnpm verify` 并汇报。
4. 提示词本体不要写在聊天里，写进仓库的 `docs/prompts/`，便于追溯。
5. 文档位置、同步规则、模型选型和关键架构决策的汇总见 `docs/prompts/2026-09-22-doc-index.md`。

### 2.2 总控提示词

```text
你是 DataPulse 项目的实现工程师。

项目路径：/Users/dundundebaba/sync/code/open/DataPulse
仓库：https://github.com/lotusTanglei/DataPulse.git

必读文档（在仓库中）：
- docs/superpowers/plans/三阶段计划.md

- README.md
- docs/known-issues.md

若上述文件不存在，先报告缺失路径并停止，不要改用其他历史文档猜测任务。

硬性约束：
1. 严格按「开发顺序」的批次编号执行，不要跨批次，不要提前做后面阶段的工作。
2. 不允许破坏现有能力：每轮结束必须运行 `pnpm verify` 并通过。
3. 不允许新增未在计划中列出的功能。
4. 不允许让核心模块 import AI 模块（AI 必须是可选模块）。
5. 一个组件只绑一个数据源；不允许实现单张图表跨数据集 join。
6. 不执行任意代码，不允许 AI 未经确认自动发布。
7. 修改前先读相关文件的当前内容，不覆盖未提交的他人修改。
8. 不要写多余注释；遵循仓库既有代码风格和约定。

每轮输出格式：
- 本批次编号与目标
- 改动的文件清单
- 新增/修改的测试
- `pnpm verify` 实际结果
- 未完成或存疑的点
```

```text

1-8 字段修正入口
1-9 上下文预算治理

  _merge_type 因此只能给出 STRING。
- 类型冲突收敛规则：数值优先 → 时间优先 → 字符串兜底。
```

### 2.6 验收提示词

```text
对照「三阶段计划」的验收门禁，逐条核对当前代码，输出：

1. 每条门禁的当前状态（通过 / 未通过 / 无证据）
2. 支撑证据（测试名、命令、报告路径）
3. 未通过项的最小可复现步骤
4. 不允许用「预计」「应该」等措辞；没有证据就写「无证据」

第一阶段门禁：
- 首次成功率 ≥ 90%
- 失败时 100% 仍产出可编辑草稿
- CSV 数值/日期识别 ≥ 95%
- 字段绑定准确率 ≥ 85%
- 可生成 ≥ 25 组件大屏
- 一键复跑可用

第二阶段门禁：
- 空图表 = 0、重叠 = 0、越界 = 0
- 首次可用率 ≥ 95%，平均修改 ≤ 2
- 语义匹配 ≥ 95%
- 同 Plan 编译可复现
- 3 个多源场景跑通

第三阶段门禁：
- 模型升级 0 回归
- 无 AI 最小部署可用
- 一日内完成「接入数据 → 生成 → 发布 → 嵌入」
```

## 三、使用节奏建议

| 轮次 | 内容 | 结束条件 |
| --- | --- | --- |
| 1 | 批次 1 | 画像可用 + 类型推断测试通过 |
| 2 | 批次 2 | 部分非法仍出草稿 + ≥ 25 组件可生成 |
| 3 | 批次 3 | 基线报告归档 |
| 4 | 批次 4-6 | M1 门禁通过后进入 |
| 5 | 批次 7-8 + 组件第一批 | M2 门禁 |
| 6+ | 批次 10 起 | M3 门禁 |

**每轮只喂一个批次**，让 AI 有足够上下文把测试和边界情况做扎实。一次给全部阶段，必然出现偷工减料和跨批次返工。
