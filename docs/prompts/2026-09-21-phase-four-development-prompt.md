## 二、架构和设计约束

- 沿用 Vue 3 / TypeScript / Vite、Python / FastAPI、Pydantic、SQLAlchemy / Alembic 和现有 pnpm / uv 工具链。
- 后端代码落在本项目 `apps/server` 的职责模块；前端落在 `apps/web`，共享合同和 SDK 使用 `packages`。遵守项目专用后端原则，不向其他项目的 `backend/sunbox` 添加代码。
- 保留模块化单体、私有部署和现有 Docker 交付体验。根据已验证的容量问题增加必要能力，不预先引入微服务、Redis、Kafka 或 Kubernetes。
- 复用现有查询安全内核、发布快照、资产管理、AI Gateway、数字人 speech worker 和 Embed SDK。先确认已有能力及缺口，避免重复建设。
- 新合同遵循现有版本、导出和类型生成链路；数据库调整使用追加迁移，覆盖已有数据升级，不能改写已应用迁移或手工修改生成产物来掩盖漂移。
- 不破坏无 AI、无 TTS 供应商时的编辑、发布、播放和字幕降级；AI 写入草稿与人工确认发布的边界继续有效。
- 新增管理界面要包含真实请求、持久化、权限、加载、空态、错误态和键盘可用性，并与现有界面一致。

## 三、必须覆盖的开发范围

先建立范围矩阵，逐项列出「需求、现有实现、实际缺口、交付物、测试、目标环境条件」。下面的边界是建议的首版设计起点；涉及尚未决定的产品语义时明确记录假设，不把建议写成已经确认的历史需求。

### 1. 多用户协作与权限

- 把单管理员模式平滑演进为多用户管理，保留现有管理员和历史资源的可用性。
- 明确账号生命周期、角色、资源归属、授权与撤销、审计及旧账号迁移规则。
- 以管理端资源与操作权限作为首版设计起点，覆盖数据源、数据集、文件/媒体、大屏、发布、插件和系统设置。形成可执行的权限矩阵，明确哪些能力属于本阶段的「复杂权限」。
- 读写鉴权必须由服务端统一执行，覆盖列表、详情、预览、查询、导入导出、发布及资产下载；不能只隐藏按钮。角色变更、账号停用和授权撤销要有明确的会话与缓存失效语义。
- 协作至少覆盖资源共享和多人编辑冲突检测，禁止静默覆盖他人修改；明确版本冲突提示与解决流程。是否需要实时共同编辑应依据范围设计确认，不能将普通共享冒称实时协作。
- 宿主系统继续承担观看者身份与业务授权，保持 Studio 权限与 Embed Ticket 边界清晰。部门组织树、行列级数据权限和外部身份联邦不得作为未说明的隐含范围。

### 2. 模板与组件市场

- 实现可用的目录、详情、版本和兼容性展示、安装或导入、使用、升级及卸载流程；内置模板列表不能作为市场交付。
- 首版优先采用适合私有部署的受控目录/离线包机制，明确资源来源、许可证、依赖、内容完整性和管理权限。公共交易平台、支付和商业结算不作为默认范围。
- 模板导入要处理组件、数据集和资产引用重映射；包中不得包含数据库密码、供应商密钥、Session、Ticket 或宿主 API Key。
- 升级与卸载必须处理已被草稿和发布内容引用的版本，防止已发布大屏被悄悄改变或资源被误删。
- 安装失败、版本不兼容、包损坏、依赖缺失和不允许的内容都应给出稳定错误，不能留下半安装状态。

### 3. 插件 SDK 与加载器

- 依据路线中的插件约定，定义并实现 manifest、ID/版本、兼容范围、组件元数据、属性和数据输入 Schema、默认配置、资源与配置迁移。
- 完成组件注册、编辑器属性配置、预览、发布、独立播放和 Embed 的完整接入；交付至少一个可构建、可安装、可运行的示例插件及开发文档。
- 插件消费受控运行时数据，不持有数据库凭据、不绕过查询鉴权；缺失、异常或不兼容插件应局部降级，不能拖垮整屏。
- 保持管理员安装、同源可信代码的既定模型，明确其信任边界。组件错误捕获不等于恶意代码沙箱，不能宣称安全隔离未实现的不可信插件执行。
- 发布内容引用明确的插件版本，提供升级兼容性检查和回退策略。不要把现有 Embed SDK 当作组件插件 SDK。

### 4. 导入导出、备份恢复与升级

- 明确备份边界，覆盖元数据库、上传文件、媒体、发布依赖及必要配置；验证数据库和文件引用的一致性。
- 凭据密文的恢复依赖要有专门说明，密钥通过受控渠道独立管理，不能把明文密钥写入普通导出包、日志或测试证据。
- 提供备份、完整性检查、恢复预检、隔离恢复验证和失败处理流程。恢复到已有实例时必须明确冲突与覆盖语义。
- 处理包损坏、路径穿越、资源缺失、版本不兼容和迁移失败。备份生成成功不能替代恢复验收。
- 在干净实例演练完整恢复，验证登录、查询、编辑、发布、独立播放、Embed 和数字人资源；记录实际恢复时间与适用规模。

### 5. 规模化质量、运维与安全

- 核对 API 与独立 speech worker 的并发领取、任务中断、重启、多实例竞争、配额和容量治理，不能仅以单进程测试宣称跨主机可用。
- 落实结构化日志、request ID、低基数指标、告警接收验证、诊断、保留清理和运维手册；复用现有 Prometheus 配置。
- 对上传文件和媒体落实实际扫描器接入与处理隔离，并明确失败策略；模拟扫描器只用于本地回归。
- 在已定义的资源规格和负载下验证查询并发、缓存、发布播放、数字人队列和资源上限。沿用既有性能门槛；尚未量化的指标在测试前定义，不得根据结果事后放宽。
- 保持精确 Origin、CSP、CSRF、可信代理、只读查询、SSRF 防护、密钥脱敏和访问撤销等边界。

## 四、八项目标环境门禁

逐项执行 `docs/PHASE_FOUR_TARGET_ENVIRONMENT.md`，保留原编号和关闭标准：

| 编号 | 必须验证的内容 |
| --- | --- |
| P4-ENV-001 | 组织实际浏览器/密码管理器组合，登录可填充，数据库表单不误填管理员凭据 |
| P4-ENV-002 | 将要上线的完整 LB/WAF/CDN/代理链、TLS、CSP、客户端 IP、缓存和日志脱敏 |
| P4-ENV-003 | 物理 4K、高 DPI、深浅主题、画布和图表清晰度、减少动效 |
| P4-ENV-004 | 目标浏览器/代理/kiosk 条件下连续 8 小时播放及每分钟资源趋势 |
| P4-DH-001 | 专用真实 TTS 供应商的端到端合成、故障、语言降级、缓存和用量 |
| P4-DH-002 | 真实跨域媒体、播放/Embed 矩阵、字幕时钟、用户手势和完整无障碍 |
| P4-DH-003 | 目标环境首帧/字幕/音频基线、8 小时数字人长播和跨主机调度 |
| P4-DH-004 | 生产指标告警、结构化日志、重启演练、容量治理、扫描器和处理隔离 |

- 环境与数字人可复用同一次 8 小时窗口，但必须分别保存对应指标并判定结果。
- P4-ENV-004 沿用连续 28,800 秒、所有查询完成无失败、既有七绑定组件 fixture 最大在途不超过 7、JS 堆总增长低于 128 MiB 且无失控增长等标准。不得把该 fixture 的并发数当作所有负载的全局容量定义。
- 开始前识别真实环境、测试账号、设备和监控是否具备。缺少外部条件时记录具体阻塞，同时完成不依赖它的实现、自动化、脚本与操作手册，不要让一个环境阻塞中断全部开发。
- 不得用 fake model/TTS、HTTP mock、本机代理、仿真 4K 或短时 soak 关闭真实环境门禁。失败、skip、deselect、未执行和阻塞不得计为通过。
- 仅使用专用测试凭据和 fixture；不要采集或输出生产凭据、客户数据及完整敏感话术。

## 五、执行与验证方式

1. 先给出简短的基线结论、范围冲突处理、缺口矩阵和执行顺序。把详细设计写入 `docs/superpowers/specs/`，按权限协作、生态插件、备份运维等职责拆分实现计划到 `docs/superpowers/plans/`。
2. 对已明确范围直接推进。普通实现选择自行判断并记录；只有产品边界无法由仓库推断或关键外部条件缺失时，提出具体问题，并继续推进不依赖答案的任务。
3. 每个交付切片形成合同、迁移、服务端、前端、权限、测试和文档闭环。涉及行为变更时编写能证明真实场景与失败边界的回归，避免只验证实现细节。
4. 持续维护 `docs/PHASE_FOUR_PROGRESS.md`，将功能完成、本地验证、目标验收与外部阻塞分列记录；同步维护已知问题，不删除历史失败证据。
5. 按当前 `package.json` 和测试工具说明运行验证，不猜测参数或虚构执行结果。至少覆盖：

   ```bash
   pnpm verify
   pnpm test:integration
   pnpm test:e2e
   pnpm test:e2e:cross-browser
   ```

   另外执行变更涉及的权限负向用例、迁移、安装升级、插件兼容、备份恢复、Docker 全新启动和故障演练。数字人回归使用现有 fixture 配置，确认测试实际执行而非跳过。

6. 物理显示与长播在符合门禁条件的环境执行：

   ```bash
   pnpm test:e2e:display

   DATAPULSE_E2E_SOAK_SECONDS=28800 \
   DATAPULSE_TARGET_EVIDENCE_DIR=test-evidence/phase-four/soak \
   pnpm test:e2e:soak
   ```

   证据目录按实际运行使用唯一子目录，避免覆盖历史结果。保存真实命令、退出码、代码版本与工作区差异标识、环境信息、时间和脱敏证据。不能仅凭命令名断言它已连接目标部署。

7. 完成后自查需求覆盖与代码差异，对缺陷修复后运行相关回归和必要的最终门禁。测试通过后不无理由反复全量运行。
