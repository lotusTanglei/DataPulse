# 版本迁移与回滚

DataPulse 对大屏文档、组件实例、模板和编辑命令采用显式版本，并在读取或执行边界完成迁移。迁移只转换受控 JSON 数据，不执行文档中的任意代码。

## 兼容策略

- 文档版本：缺少 `schema_version` 的历史文档按 v0 读取并迁移到 v1；v1 原样读取；高于当前版本时拒绝加载。
- 组件版本：每个组件实例带 `schema_version`。缺失版本迁移到 v1；未来版本拒绝加载。组件注册表的 `ComponentContract` 继续用 SemVer 描述属性和数据输入兼容性。
- 模板版本：内置模板声明 `schemaVersion: 1`，创建文档时统一经过文档与组件迁移器。
- 编辑命令版本：历史未封装命令迁移为 `{ schema_version: 1, command }`，手工编辑与 AI 预览采用同一执行入口；未来版本拒绝执行。

版本提升必须添加逐版本迁移函数、旧版 fixture、迁移后快照和未来版本拒绝测试。禁止静默忽略未知字段或降级未来版本。

## 升级与回滚验证

在发布新镜像前运行：

```bash
pnpm verify:upgrade-rollback
```

该命令执行 Alembic 从空库升级、合同版本迁移，以及真实备份、恢复、重启、发布、独立播放、嵌入和权限演练。详细备份操作见 [备份恢复](backup-restore.md)。

升级前在维护窗口创建并校验备份，记录应用版本和 Alembic head。恢复时先使用创建备份的同一版本启动并验证，再升级恢复实例。回滚时停止新版本，保留失败升级后的目录用于排查，并让旧版本重新指向升级前完整保留的数据目录；不得用新版本写过的数据目录直接启动旧版本。
