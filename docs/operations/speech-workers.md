# Speech worker consistency

All processes must run the same application/schema release, share the metadata database, managed media directory and canonical data directory, and have synchronized UTC clocks. Migration `0021_speech_leases` introduces durable worker ownership and audio reservations. Stop older workers during this upgrade; an old worker does not honor the new terminal-state or quota protocol.

Admission checks the daily task count and per-component cooldown in the same transaction that enqueues the task. SQLite uses `BEGIN IMMEDIATE`; PostgreSQL uses the singleton settings row as a transaction lock. Worker claims retain the queued-to-running conditional update. Completion and cancellation are terminal: a late callback cannot overwrite a cancelled/failed/succeeded result or attach a late asset.

A worker owns a running task for 60 seconds and renews its lease every 10 seconds. Startup and the worker's periodic recovery only fail expired queued tasks and running tasks whose lease expired or is absent. A live worker survives an API restart. A killed worker's task becomes `SPEECH_TASK_INTERRUPTED` after its lease expires and is never automatically replayed. Graceful shutdown cancels local work and records interruption where the process still owns the lease. If the database cannot confirm ownership, execution is cancelled; recovery resolves the expired lease later.

Before contacting a provider, a worker reserves up to the maximum speech duration from the remaining daily audio capacity. Parallel workers subtract existing reservations before admitting synthesis. Successful completion reconciles the reservation with the actual accepted duration and persists the result and usage atomically; failure, cancellation and expired leases release capacity. A task that produces audio longer than its remaining reservation fails and deletes the unreferenced media. Cached playback does not reserve synthesis seconds. Reservations are charged to their UTC reservation day so an in-flight task does not silently move reserved capacity between days.

These limits govern accepted generated audio and durable task admission. They cannot undo a billable request already received by an external provider. Cancellation, worker loss, malformed provider output or duration rejection can still incur provider charges; reconcile provider billing independently. The synthesis-attempt counters retain attempted work separately from accepted audio. Package/media processing and provider calls must also obey the deployment's concurrency and resource limits.

Restoring a backup invalidates pending/running speech tasks and removes their worker leases/reservations so restoration cannot play old queued speech. To speak again, create a fresh task after validating the restored provider and screen.

Local coverage uses separate SQLAlchemy engines/sessions against an actual migrated SQLite database, deterministic concurrent admission, two-worker claims, reservation reconciliation, lease renewal/recovery, and remote cancellation with late asset cleanup. PostgreSQL locking follows the same transaction design but requires the target PostgreSQL integration/restart drill before claiming that topology has been validated.
