# DataPulse 开发顺序

日期：2026-09-22
依据：`三阶段计划.md`（v3）
相关：`../prompts/2026-09-22-ai-model-and-development-prompts.md`

本文把三阶段方案拆成可执行的开发批次，明确任务编号、依赖、产出和验证方式。

## 一、执行原则

1. **按依赖排序，不按重要程度排序。** 没有画像就没有规划，没有编译器就没有视觉评分。
2. **每个批次都要有可运行的验证**，不留「以后再测」。
3. **度量先行。** 第一阶段就要建好质量采集，否则后面无法判断改造是否有效。
4. **组件与平台并行。** 组件扩充和主线无强依赖，可独立推进。
5. **每批次结束后跑全量 `pnpm verify`**，保持基线绿灯。

## 八、风险前置项

必须在早期处理，否则会阻塞后续：

1. **`DatasetProfile` 是规划层的前提** —— 批次 1 不得延期。
2. **结构化输出的 provider 兼容性** —— 批次 2 先探测再决定默认行为。
3. **模板骨架抽象会影响所有模板** —— 批次 5 落地后立即跑视觉回归。
4. **组件合同版本化** —— 第一个新组件就要定规范，不能等到第二批。
5. **AI 模块边界** —— 批次 13 之前不能出现核心模块 import AI 的新代码。
