# DataPulse 产品愿景与技术路线设计

- 状态：已确认
- 日期：2026-07-29
- 许可证：Apache-2.0
- 交付形态：可私有化部署的 Web 系统

## 1. 背景

DataPulse 是一个从零开始建设的开源数据分析与大屏展示软件。项目调研覆盖了 Vue/React 大屏模板、ECharts/DataV 项目、拖拽式编辑器、Three.js 工业可视化和 Cesium 数字城市等方向。

调研项目多数属于以下三类：

1. 固定数据和固定布局的大屏演示。
2. 可复用的行业模板集合。
3. 具备拖拽、配置和数据绑定能力的可视化编辑器。

DataPulse 不以复制其中某个项目为目标。现有项目主要用于参考图表封装、屏幕适配、编辑器交互和插件设计。DataPulse 的差异化来自“轻量数据分析 + 专业大屏编辑 + AI 原生创作 + 安全嵌入”的完整闭环。

## 2. 产品愿景

> DataPulse 是一个 AI 原生、可私有化部署、可嵌入其他系统的数据分析与大屏创作平台。

用户可以通过三种方式把数据转化为可视化：

1. 拖拽字段并配置图表。
2. 编写 SQL。
3. 使用自然语言生成分析、图表或完整大屏。

产品的主要用户是懂业务和数据、但不希望编写前端代码的数据分析师和运营人员。软件实施团队是次要用户，他们可以通过项目导入导出、组件插件和嵌入协议快速交付客户项目。

## 3. 产品边界

### 3.1 核心能力

- 数据库、文件和 REST API 数据接入。
- 轻量数据加工、聚合和查询。
- 图表创建和大屏拖拽编辑。
- 定时刷新和查询缓存。
- 组件插件。
- AI 辅助分析、图表生成和大屏生成。
- 不可变版本发布。
- 安全 iframe 嵌入和宿主通信。
- Docker 私有化部署。

### 3.2 权限边界

DataPulse 不建设复杂的企业用户、组织和数据权限体系。

- 编辑端采用单管理员模式。
- 宿主系统负责最终用户登录、组织、角色和业务权限。
- DataPulse 只验证大屏级 Embed Ticket。
- 不同获准观看者默认看到相同的大屏和数据。
- 宿主系统可以在受签名的 Ticket 中传递大屏参数。
- DataPulse 不实现行级、列级或部门级权限。

### 3.3 明确不做

- 多人实时协作。
- 组织架构、复杂角色和细粒度数据权限。
- 模板市场和插件市场。
- 完整 ETL、数据仓库和数据质量平台。
- 企业指标语义层。
- 3D 数字孪生和 Cesium GIS。
- 移动端独立编辑器。
- 微服务和分布式中间件。
- AI 自动执行任意 Python、JavaScript 或写入 SQL。
- AI 未经人工确认自动发布生产大屏。

## 4. 架构路线选择

### 4.1 候选路线

#### Python 模块化单体

FastAPI 同时承载数据源、查询、AI、调度、发布和嵌入模块。DuckDB 处理文件数据和本地分析。

优点是数据与 AI 生态直接、部署简单、模块间通信成本低。缺点是需要严格约束后台任务、查询并发和数据库驱动兼容性。

#### Java 主服务加 Python 分析服务

Java 负责企业集成和数据库访问，Python 负责 AI 与数据分析。

优点是 JDBC 和企业组件成熟。缺点是从第一天引入双后端、双模型和服务通信，增加部署与调试成本。

#### 浏览器侧分析

在浏览器内使用 DuckDB-Wasm 等能力分析数据，后端只负责元数据和资源。

优点是服务器轻。缺点是浏览器内存、数据库凭据、大文件和嵌入安全难以控制。

### 4.2 决策

采用 Python 模块化单体。

所有后端模块运行在同一个应用中，但通过明确接口隔离。将来只有在单实例无法满足实际负载时，才允许把调度器或查询执行器拆成独立进程。

## 5. 技术栈

### 5.1 前端

| 领域 | 选择 |
| --- | --- |
| 框架 | Vue 3、TypeScript、Vite |
| 状态管理 | Pinia |
| UI 组件 | Element Plus |
| 图表 | Apache ECharts |
| 画布交互 | Moveable、Selecto |
| 样式 | SCSS、CSS Variables |
| 流式响应 | Server-Sent Events |
| 单元测试 | Vitest |
| 端到端测试 | Playwright |
| 包管理 | pnpm |

编辑画布使用绝对定位 DOM 容器。ECharts、文本、图片、表格和插件组件分别渲染在独立容器中。业务组件不绘制到单一 HTML Canvas 中。

### 5.2 后端

| 领域 | 选择 |
| --- | --- |
| 语言基线 | Python 3.13 |
| Web 框架 | FastAPI |
| 数据校验 | Pydantic |
| 元数据 ORM | SQLAlchemy 2.x |
| 数据库迁移 | Alembic |
| 本地分析 | DuckDB |
| 列式数据交换 | PyArrow |
| SQL AST | SQLGlot |
| 定时调度 | APScheduler |
| HTTP 客户端 | HTTPX |
| Token | PyJWT、cryptography |
| 测试 | pytest |
| 依赖与环境 | uv |
| ASGI Server | Uvicorn |

项目以 Python 3.13 生成依赖锁文件，同时在 CI 中验证 Python 3.14。开发机当前的 Python 3.14.3 可用于兼容性测试，标准开发环境由 uv 管理，不依赖全局 Python。

### 5.3 存储与部署

- 默认元数据库：SQLite。
- 可选生产元数据库：PostgreSQL。
- 默认资源存储：本地持久化目录。
- 后续资源存储扩展：S3/MinIO 兼容接口。
- 默认部署：一个 Docker 镜像和一个持久化目录。
- 可选部署：Docker Compose 加 PostgreSQL。
- 前端构建产物由同一应用提供。
- MVP 使用单个 Uvicorn Worker 和一个进程内调度器。
- 不引入 Redis、Celery、Kafka、Kubernetes。
- 默认关闭遥测。

```text
DataPulse
├── apps
│   ├── web
│   │   ├── data-workbench

│   │   ├── ai-copilot
│   │   ├── player

│   │   └── system-settings
│   └── server
│       ├── datasource
│       ├── dataset
│       ├── query
│       ├── dashboard
│       ├── publishing
│       ├── embedding
│       ├── scheduler
│       ├── cache
│       ├── ai
│       ├── plugins
│       └── system
├── packages
│   ├── schema
│   ├── plugin-sdk
│   └── embed-sdk
└── plugins
    └── builtin
```

模块依赖遵守以下方向：

- `datasource` 提供连接能力，不依赖大屏和 AI。
- `query` 使用 `datasource` 执行受控查询。
- `dataset` 描述查询，不直接渲染图表。
- `dashboard` 引用数据集，不保存数据库密码。
- `publishing` 从草稿生成不可变快照。
- `embedding` 只加载已发布快照。
- `ai` 调用 Schema、查询和图表规范接口，不绕过安全层。
- `plugin-runtime` 通过稳定协议注册组件，不访问编辑器内部状态。

## 7. 长期协议

实现开始前先固定六个版本化协议。

### 7.1 DashboardDocument

大屏草稿和发布快照的文档格式。

```json
{
  "schemaVersion": 1,
  "canvas": {},
  "theme": {},
  "parameters": [],
  "components": [],
  "interactions": []
}
```

组件实例统一包含：

- 组件 ID 和类型。
- 插件 ID 和版本。
- 位置、尺寸、旋转角度和层级。
- 数据绑定。
- 业务属性。
- 样式。

### 7.2 ChartSpec

手工操作和 AI 生成最终使用同一个图表描述。

```json
{
  "datasetId": "sales",
  "dimensions": ["month"],
  "measures": [
    {
      "field": "amount",
      "aggregation": "sum"
    }
  ],
  "filters": [],
  "sort": [],
  "limit": 1000,
  "visual": {
    "type": "line",
    "title": "月度销售趋势"
  }
}
```

DataPulse 将 ChartSpec 编译为安全查询和 ECharts Option。AI 不直接生成可执行 JavaScript。

### 7.3 DatasetDefinition

描述数据来源、字段、查询、参数、缓存和刷新策略。图表、AI 和调度器只通过数据集访问数据。

### 7.4 AnalysisPlan

AI 在生成 SQL 前输出的结构化分析意图，包括：

- 用户问题。
- 相关数据集。
- 维度和指标。
- 聚合方式。
- 过滤、排序和限制。
- 推荐可视化。
- 风险和需要确认的假设。

### 7.5 PluginManifest

描述插件 ID、版本、兼容范围、组件、配置 Schema、数据输入、资源和迁移函数。

### 7.6 EmbedProtocol

定义 Ticket 声明、iframe 加载参数和 `postMessage` 消息。

支持的消息包括：

- `ready`
- `refresh`
- `setParameters`
- `getParameters`
- `fullscreen`
- `exportImage`
- `error`
- `aiQuestion`

所有消息必须校验来源 Origin、目标窗口和消息 Schema。

## 9. 功能设计

### 9.1 项目与发布

- 创建、复制、重命名和删除大屏。
- 草稿自动保存。
- 预览和全屏播放。
- 发布不可变版本。
- 发布撤回和历史回滚。
- 导入、导出 `.datapulse` 项目包。
- 导出内容不包含数据源凭据。

### 9.2 数据源

首批内置连接器：

- PostgreSQL。
- MySQL/MariaDB。
- SQLite。
- CSV。
- Excel。
- JSON。
- REST API。

共有能力：

- 测试连接。
- 浏览 Schema、表、视图和字段。
- 字段类型识别。
- 凭据加密和环境变量引用。
- 查询超时、最大行数和并发限制。

后续连接器包括 SQL Server、Oracle 和 ClickHouse，但不改变连接器协议。

### 9.3 轻量分析

- 从表、视图或自定义 SQL 创建数据集。
- 数据预览和字段统计。
- 字段重命名、隐藏和类型调整。
- 筛选、排序、分组和聚合。
- 计算字段。
- 同一数据源内的简单关联。
- 查询参数。
- 实时查询和缓存快照。
- 手动、页面间隔和服务端定时刷新。

不支持跨数据库关联和可视化 ETL。

### 9.4 内置组件

- 指标卡。
- 文本、图片、图标和链接。
- 表格和轮播表格。
- 折线图和面积图。
- 柱状图、堆叠柱状图和条形图。
- 饼图和环形图。
- 散点图。
- 雷达图。
- 仪表盘。
- 漏斗图。
- 进度条。
- 基础 GeoJSON 地图。
- 时间、视频和 iframe。

图表支持维度、指标、聚合、过滤、排序、Top N、标题、图例、坐标轴、标签、颜色、动画和主题变量。

### 9.5 大屏编辑器

- 自定义和预设画布尺寸。
- 拖动、缩放和旋转。
- 网格、吸附线和智能对齐。
- 多选、组合、锁定和隐藏。
- 图层排序。
- 复制、粘贴、克隆和删除。
- 撤销、重做和快捷键。
- 缩放、适应窗口和全屏预览。
- 背景和全局主题。
- 等比缩放、铺满和适应宽度播放模式。
- 点击组件更新全局筛选参数。

### 9.6 AI

正式能力：

- 模型端点、模型名和 API Key 配置。
- Schema 检索。
- 自然语言生成 AnalysisPlan。
- 自然语言生成查询和图表。
- 自然语言修改已有图表。
- 图表类型和字段映射建议。
- 查询结果趋势、异常和摘要。
- 流式生成过程。
- SQL 展示和人工确认。

Beta 能力：

- 嵌入端问答，只访问当前发布大屏的数据集。
- 一句话生成完整大屏，生成四至八个候选图表并使用预设布局。

一句话生成的大屏始终保存为草稿，不能自动发布。

模型适配层兼容 OpenAI 风格 API，并允许配置自定义 Base URL。云端和本地模型共用同一个接口。第一版不引入通用 Agent 框架。

### 9.7 定时刷新与缓存

- 分钟、小时、天和 Cron 周期。
- 手动立即执行。
- 查询结果物化为 Parquet。
- 缓存有效期。
- 任务状态、错误和耗时。
- 同一数据集防重入。
- 发布大屏优先读取有效缓存。
- 缓存失效后按策略查询源数据。

### 9.8 插件

组件插件由 `manifest.json`、ES Module Bundle、图标和资源组成。

插件声明：

- ID、版本和兼容版本。
- 组件名称和分类。
- 属性配置 JSON Schema。
- 数据输入 Schema。
- 默认配置。
- 渲染器。
- 配置迁移函数。

插件从管理员配置的容器挂载目录加载，在同源页面运行，视为可信代码。普通观看者不能安装插件。

数据连接器插件先定义后端接口，首批官方连接器以源代码内置方式交付。

## 10. 关键流程

### 10.1 制作

```text
连接数据源
→ 创建数据集
→ 预览和加工
→ 创建图表
→ 加入画布
→ 调整布局
→ 保存草稿
→ 发布不可变版本
```

### 10.2 AI 创作

```text
自然语言问题
→ 检索相关 Schema
→ 生成 AnalysisPlan
→ 生成 ChartSpec
→ 编译 SQL
→ 安全检查
→ 限时限量执行
→ 生成图表和解释
→ 用户确认
→ 写入草稿
```

### 10.3 嵌入

```text
宿主后端持有长期 API Key
→ 请求短期 Embed Ticket
→ 浏览器加载 iframe
→ 验证 Ticket、Origin、大屏和有效期
→ 加载不可变发布版本
→ 查询或读取缓存
→ 渲染
→ 通过 postMessage 与宿主通信
```

长期 API Key 不进入浏览器。

## 11. 安全设计

### 11.1 数据源

- 使用 AES-GCM 加密连接配置。
- 加密主密钥只通过环境变量或挂载 Secret 注入。
- 推荐所有外部数据库使用只读账号。
- 禁止多语句查询。
- SQLGlot AST 只允许查询类语句。
- 查询同时受数据库权限、语句超时、行数限制和并发限制保护。
- REST 数据源限制协议、重定向、响应大小和超时，防止 SSRF。
- 日志对密码、Token 和 API Key 脱敏。

### 11.2 AI

- 只向模型发送完成任务所需的 Schema 和采样结果。
- 不发送数据库密码和连接字符串。
- 查询结果超过阈值时只发送聚合、采样或统计摘要。
- AI 生成的 SQL 使用与手工 SQL 相同的安全执行路径。
- AI 工具没有文件系统、Shell 和任意代码执行权限。

### 11.3 嵌入

- 宿主后端用长期 API Key 换取短期 Ticket。
- Ticket 包含大屏 ID、发布版本、有效期、允许 Origin、AI 开关和受签名参数。
- Token 不放入长期可复用 URL。
- 使用 CSP `frame-ancestors`。
- 提供 iframe sandbox 推荐值。
- 所有 `postMessage` 调用校验 Origin 和消息 Schema。
- 支持 API Key 轮换、Ticket 失效和发布撤回。

## 12. 错误处理

后端返回稳定错误码和请求追踪 ID。错误按以下类别组织：

- `DATASOURCE_*`：连接和驱动错误。
- `QUERY_*`：语法、权限、超时、限行和取消。
- `DATASET_*`：字段、参数和依赖错误。
- `DASHBOARD_*`：文档、组件和版本错误。
- `PLUGIN_*`：缺失、版本不兼容和加载失败。
- `EMBED_*`：Ticket、Origin 和发布状态错误。
- `AI_*`：模型、结构化输出、上下文和安全拒绝。
- `SCHEDULE_*`：任务冲突、执行和缓存错误。

编辑器显示可操作的错误说明。发布播放器采用组件级失败隔离：单个组件失败时显示占位和请求 ID，不阻塞其他组件渲染。

AI 生成失败时保留用户输入、已生成的 AnalysisPlan 和错误阶段，用户可以重试或转为手工编辑。

## 13. 容量与性能基线

- 单实例基线：2 核 CPU、4 GB 内存。
- 单大屏建议不超过 40 个可视组件。
- 单图默认最多返回 5,000 行。
- 查询默认超时 30 秒。
- 单实例目标支持 50 个并发观看连接。
- 发布播放器首屏目标为 3 秒左右，不包含外部数据库自身的慢查询时间。
- AI 不读取全表，模型上下文受大小限制。
- 超过基线时优先使用查询缓存和增加单实例资源。

容量基线是架构验收目标，不是项目时间计划。

- 插件缺失和错误隔离。
- AI 流式响应和失败恢复。

### 14.4 AI 评测

- 使用固定 Schema 和问题集。
- 校验 AnalysisPlan 与 ChartSpec 的结构。
- 校验只读 SQL 和字段引用。
- 校验拒绝写入、越权数据集和任意代码请求。
- 模型升级前运行回归评测。
- AI 测试不以文案逐字一致作为通过条件。

### 14.5 发布门槛

- 所有协议 Schema 有版本和迁移测试。
- 内置连接器通过统一契约测试。
- 嵌入安全负向用例通过。
- 发布播放器能够隔离单组件错误。
- 无 AI 配置时核心功能完整可用。
- Docker 全新启动和数据卷恢复测试通过。

## 15. 实施顺序

路线只表达依赖关系，不绑定时间：

1. 建立仓库、开发环境、CI 和 Apache-2.0 许可证。
2. 定义六个长期协议及其 JSON Schema。
3. 实现元数据库、数据源、数据集和查询安全内核。
4. 实现统一组件运行时和内置图表。
5. 实现大屏编辑器。
6. 实现草稿、发布快照和播放器。
7. 实现 Embed Ticket、CSP 和 Embed SDK。
8. 实现 AI 分析内核、制作端 Copilot 和 AI 评测。
9. 实现嵌入问答和整屏生成 Beta。
10. 实现定时刷新、Parquet 缓存和任务诊断。
11. 实现组件插件 SDK 和插件加载器。
12. 完善导入导出、备份恢复、文档和开源发布流程。

每一步都必须在前一步的协议与测试基础上完成，不以快速生成大量页面替代可验证的内核。
