# 独立产品候选：受控对话数字人 v1 设计

- 状态：第一版候选设计，暂不纳入 DataPulse 产品路线
- 日期：2026-09-12
- 产品归属：独立产品孵化候选，不占用 DataPulse 第四阶段
- 前置能力：第三阶段数字人播报、统一 QueryResult 运行时、权限边界、AI Gateway、TTS 与 Embed SDK
- 依赖关系：可复用 DataPulse 第三阶段数字人能力，需单独建立产品、服务和运维边界

本文件保留用户提出的 AI 对话数字人方向作为独立产品的早期设计，不构成 DataPulse 当前阶段承诺，也不改变 DataPulse 四阶段路线。

## 1. 目标

让用户通过文字或语音询问当前大屏中的授权数据，获得带数据依据的回答，并继续进行有限轮次追问。数字人负责理解问题、调用受控数据工具、生成回答、播放语音和显示字幕；它不直接访问数据库，也不拥有任意代码执行能力。

v1 的产品承诺是“看得懂当前大屏并能回答数据问题”，包括：

- 询问当前屏幕的指标、趋势、排名、异常和时间范围；
- 追问“那华东呢”“和昨天比呢”等依赖上一轮上下文的问题；
- 将回答定位到来源组件或指标，并允许用户展开查询依据；
- 在文字、字幕、音频不可用时逐级降级；
- 在权限不足、数据过期、问题超出范围时明确说明原因。

## 2. v1 范围

### 2.1 支持的输入

第一版同时支持文本输入和浏览器语音输入。语音输入使用浏览器或配置的 ASR 适配器，ASR 只返回转写文本和置信度，不直接决定工具调用。用户可查看、修改转写文本后再提交。

### 2.2 支持的对话能力

| 能力 | v1 行为 |
| --- | --- |
| 当前屏幕问答 | 读取已发布文档中当前用户可见的组件结果 |
| 指标解释 | 解释数值、单位、时间范围、排名和变化原因候选 |
| 条件追问 | 保留屏幕、指标、时间范围、筛选条件和上一轮结果 |
| 数据筛选 | 通过受控参数改变当前视图，需先展示拟执行筛选 |
| 播报回答 | 文本、字幕、TTS 按现有数字人队列播放 |
| 依据查看 | 展示来源组件、查询时间、数据新鲜度和脱敏摘要 |
| 转人工/结束 | 用户可停止播报、清空会话或回到静态播报 |

### 2.3 明确不纳入 v1

- 开放域闲聊、情感陪伴、人格扮演和自由创作；
- 任意 SQL、任意 URL、任意 JavaScript/HTML 或数据库直连；
- 修改数据、删除数据、发布大屏、修改权限或发送外部消息；
- 无授权跨屏搜索、跨租户查询和绕过宿主系统身份；
- 实时视频驱动口型、复杂表情和多人协同对话；
- 自动将 AI 回答写入正式话术或发布快照。

## 3. 用户流程

1. 用户打开已发布大屏，数字人显示“可提问”状态和当前数据更新时间。
2. 用户输入文字或说话；语音转写结果先显示在输入框中。
3. 服务端创建 `ConversationTurn`，绑定用户、屏幕、发布版本、组件范围和请求 ID。
4. 对话编排器判断问题是否属于支持范围，并生成结构化工具计划。
5. 策略层校验工具、参数、权限、数据新鲜度和调用预算。
6. 工具返回结构化结果；模型只根据工具结果生成回答，不凭空补充数值。
7. 页面先显示文字和来源，再按用户设置播放字幕/TTS；播放失败只影响数字人输出。
8. 用户可以追问、重新生成、查看依据、停止播放或清空会话。

## 4. 系统结构

```text
文本/ASR
   -> Conversation API
   -> Conversation Orchestrator
      -> Context Store
      -> Policy Guard
      -> Query/Screen/Playback Tools
      -> AI Gateway
   -> Answer + Evidence
   -> DigitalHuman Runtime
      -> Subtitle / TTS / Embed SDK events
```

### 4.1 会话上下文

上下文保存结构化引用，不保存未经必要性判断的完整查询结果。核心字段包括：

- `conversation_id`、`turn_id`、用户与宿主实例标识；
- 屏幕 ID、发布版本、组件 ID、数据集 ID 和当前筛选参数；
- 最近 5 轮用户问题、工具调用摘要和回答摘要；
- 数据时间戳、时区、语言、回答模式和剩余预算；
- 脱敏后的错误码和来源引用。

会话默认 30 分钟无活动后过期。清空会话立即删除上下文；审计记录保留必要元数据，不保存完整敏感话术和原始查询结果。

### 4.2 受控工具

v1 只开放以下工具，工具参数全部使用服务端合同校验：

| 工具 | 用途 | 副作用 |
| --- | --- | --- |
| `screen_context` | 获取当前发布版本、可见组件和数据更新时间 | 无 |
| `metric_value` | 获取单指标当前值和时间范围 | 无 |
| `metric_compare` | 获取同比、环比或两个筛选条件的比较 | 无 |
| `metric_rank` | 获取排名和 Top N | 无 |
| `metric_trend` | 获取限定点数的趋势摘要 | 无 |
| `screen_filter_preview` | 预览拟应用的筛选条件 | 无 |
| `screen_filter_apply` | 应用已确认的筛选条件 | 改变当前视图，必须显式确认 |
| `speech_reply` | 将已确认回答提交给字幕/TTS 队列 | 播放任务 |

所有查询工具复用既有 `ScreenRuntime` 和 QueryResult 链路。`screen_filter_apply` 是 v1 唯一允许改变界面状态的工具，默认只执行预览，用户确认后才应用。

### 4.3 回答合同

```json
{
  "conversationId": "conv_01",
  "turnId": "turn_04",
  "status": "answered",
  "answer": "华东销售额为 128 万元，较昨日上升 8.4%。",
  "evidence": [
    {"componentId": "sales-region", "label": "区域销售额", "queriedAt": "2026-09-12T08:00:00Z"}
  ],
  "followUpSuggestions": ["查看华南", "按门店排名"],
  "speech": {"enabled": true, "text": "华东销售额为 128 万元，较昨日上升 8.4%。"},
  "error": null
}
```

状态至少包括 `transcribing`、`planning`、`awaiting_confirmation`、`querying`、`answered`、`speaking`、`cancelled` 和 `failed`。每个状态变化携带 `conversationId`、`turnId`、序号和 request ID，复用现有 Embed 事件校验。

## 5. 模型与提示词策略

- 系统提示词固定产品边界、语言、单位、时间和拒答规则；租户配置不能覆盖安全规则。
- 模型只能选择工具和填充合同参数，服务端拒绝额外字段、越权组件和未授权数据集。
- 工具结果使用结构化 JSON；回答中的数值、单位、时间范围必须能映射到工具结果。
- 无工具结果时只能返回“无法确认”，不能猜测或补齐数字。
- 生成后执行数值一致性、敏感信息、禁播词、长度和语言检查；失败则降级为模板化回答。
- 模型、提示词版本、工具计划和稳定错误码进入审计，不记录完整数据上下文。

## 6. 语音、字幕与数字人表现

复用第三阶段播放驱动和持久 speech worker：

- 输入语音和输出 TTS 分别受浏览器用户手势、静音和权限控制；
- 新一轮提问自动停止当前回答，迟到的音频回调不能覆盖最新状态；
- 字幕先于音频展示，字幕包含回答和必要的来源提示；
- ASR 失败回退到文本输入，TTS 失败回退到字幕，AI 失败回退到静态播报；
- Embed 宿主可订阅 `conversationState`、`answer`、`subtitleCue` 和 `error` 事件；
- 数字人头像只表达 `listening`、`thinking`、`speaking`、`paused` 和 `error` 五类状态。

## 7. 安全与治理

- 会话权限在每一轮重新绑定当前用户、宿主 Origin、屏幕发布版本和组件范围；
- 所有工具执行服务端授权，拒绝模型生成的 SQL、URL、脚本和任意文件路径；
- 敏感字段、凭据、个人信息和原始 API 响应不得进入模型上下文，继续使用现有敏感命名变体拦截；
- 数据出站前显示数据范围、目的和供应商配置；未同意时使用本地规则或拒绝；
- 会话、转写、回答、工具摘要和 TTS 任务遵守现有保留期限与删除策略；
- 每轮记录审计事件、稳定错误码、模型版本、耗时和工具名称，避免高基数完整话术标签；
- 限制单轮工具次数、上下文长度、每日会话数、音频秒数和并发数；
- 管理员可以关闭对话、仅允许文字、仅允许当前屏幕或要求人工确认筛选。

## 8. 失败与降级

| 失败 | 用户看到的结果 | 允许的后续动作 |
| --- | --- | --- |
| ASR 超时/低置信度 | 显示转写并要求确认 | 修改文字后重试 |
| 问题超出范围 | 明确支持范围 | 查看示例问题 |
| 权限不足 | 不泄露资源是否存在 | 返回当前可见数据 |
| 数据过期 | 标注更新时间 | 刷新后重试 |
| AI 超时/拒绝 | 模板化说明或静态播报 | 重新生成/结束 |
| TTS/自动播放失败 | 保留文字和字幕 | 用户手势后重播 |
| 会话冲突/切屏 | 取消旧轮次 | 以最新屏幕重新提问 |

## 9. 研发拆分与验收

### S4.0 合同与边界

冻结会话、轮次、工具、回答、事件和错误码；完成权限、敏感字段、提示词和审计设计。

### S4.1 文本问答闭环

实现当前屏幕问答、上下文追问、来源展示、拒答、限额、模板化降级和编辑器/独立播放基础入口。使用 deterministic fake model，不接真实客户数据。

### S4.2 受控语音闭环

接入 ASR 适配器、用户确认、TTS 队列、打断、字幕事件和 Embed SDK 控制；补充 Chromium/Firefox/WebKit 自动化回归。

### S4.3 数据筛选与管理策略

实现筛选预览/确认、会话管理、组织策略、数据出站提示、审计查询和用量报表。筛选之外的任何写操作继续拒绝。

### S4.4 v1 质量收口

完成权限矩阵、敏感数据泄露、工具参数模糊测试、模型超时、供应商失败、切屏竞态、长对话和成本上限回归，形成独立产品候选的技术验证报告。

### v1 通过标准

- 支持的问题全部能从工具结果追溯，数值回答与结构化结果一致；
- 连续追问至少 5 轮不丢失屏幕、指标和筛选上下文；
- 越权组件、敏感字段、任意 SQL/脚本和未确认筛选全部被拒绝；
- ASR、AI、TTS 任一环节失败时，文字或字幕仍可用；
- 新问题到文字回答的 P95 目标不超过 5 秒，用户可在任意阶段取消；
- 三浏览器和 Embed 基础路径通过，审计不含完整敏感话术或查询结果；
- fake model/TTS 全量回归通过后，独立产品再单独规划真实供应商和生产成熟度验收。

## 10. 独立产品后续

真实供应商、目标浏览器和跨域媒体矩阵、物理 4K/高 DPI、完整无障碍、连续 8 小时长播、生产指标告警、结构化日志、重启演练、跨主机调度、实际扫描器和安全部署，应在独立产品立项后建立单独的环境和生产验收手册。
