# DataPulse 第二阶段：大屏编辑、播放与安全嵌入设计

**状态：** 已批准

**日期：** 2026-07-30

**基础设计：** [DataPulse 产品愿景与技术路线设计](2026-07-29-datapulse-product-technical-route-design.md)

**前置阶段：** [DataPulse 数据源工作台设计](2026-07-29-datasource-studio-design.md)

## 1. 目标

第二阶段把第一阶段的数据源、数据集和安全查询能力扩展为完整的大屏交付闭环：

```text
选择数据集
→ 配置可视化组件
→ 在画布中编辑大屏
→ 自动保存草稿
→ 全屏预览
→ 覆盖发布
→ 独立播放或安全嵌入第三方系统
```

本阶段同时固定统一的 `DashboardDocument`、`ChartSpec`、组件协议和编辑器命令边界，使后续 AI 可以通过结构化协议生成图表和修改大屏，而不直接生成可执行 JavaScript。

## 2. 使用场景

### 2.1 独立播放

已发布大屏可以作为 DataPulse 顶层页面直接打开，适用于电视、会议室大屏、监控中心和普通浏览器。

- 路由为 `/play/{screen_id}`。
- 页面只包含大屏画布，不包含 Studio 导航或编辑器工具。
- 使用绑定单张大屏的可撤销播放密钥建立播放会话。
- 支持长期运行、手动刷新、定时刷新和全屏。
- 响应通过 CSP `frame-ancestors 'none'` 禁止被其他页面嵌入。

### 2.2 嵌入第三方系统

宿主系统负责最终用户的登录和业务权限，DataPulse 只负责验证大屏级访问凭证。

- 路由为 `/embed/{screen_id}`。
- 宿主后端使用 DataPulse API Key 申请短期 Embed Ticket。
- 浏览器和 iframe 中不出现长期 API Key。
- Ticket 绑定大屏、有效期、允许的宿主 Origin、初始参数和允许动态修改的参数名。
- 可使用轻量 JavaScript SDK 与播放器通信，也可直接使用 iframe。

### 2.3 Studio 草稿预览

管理员可以在 Studio 内预览和调试最新草稿。

- 必须具有有效管理员 Session。
- 读取草稿，不读取发布快照。
- 不产生正式分享地址。
- 预览和调试不会影响已发布大屏。

独立播放和第三方嵌入是正式发布方式；Studio 草稿预览是内部编辑能力。

## 3. 范围

### 3.1 本阶段包含

- 大屏创建、重命名、复制和删除。
- 固定或自定义画布尺寸。
- 拖拽、缩放、网格、吸附和画布缩放。
- 多选、对齐、图层排序、锁定和隐藏。
- 复制、粘贴、撤销和重做。
- 主题、背景和组件样式。
- 防抖自动保存、显式保存状态和修订冲突检测。
- 九类内置组件。
- 数据集绑定、`ChartSpec` 和安全查询。
- 全局参数和简单组件联动。
- 首次加载、手动刷新和页面级定时刷新。
- 草稿预览、覆盖发布和复制大屏备份。
- 独立播放密钥和独立播放器。
- Embed API Key、Embed Ticket、CSP 和轻量 JavaScript SDK。
- 资源上传，用于图片和 GeoJSON 地图边界。
- 组件、协议、编辑流程、播放流程和安全边界测试。

- 多账号、RBAC、组织架构和多人实时协作。

- 多张大屏轮播、播放列表和设备管理。
- 图片、PDF、视频、数据或离线包导出。
- 手机响应式断点和组件自动重排。
- 组件分组、旋转、标尺、辅助线和嵌套容器。
- 查询结果缓存、Parquet 缓存和后台 Cron。
- DuckDB、文件数据集和跨数据源关联。
- 第三方组件插件 SDK 和模板市场。
- AI 分析、自然语言转图表和自然语言修改大屏的产品功能。
- 复杂事件编排、下钻路径和任意组件连线。

## 4. 已确认的关键决策

| 主题 | 决策 |
|---|---|
| 架构 | 单一 `DashboardDocument` 和统一组件运行时 |
| 编辑与播放 | 编辑预览和发布播放器共用组件实现 |
| 发布 | 草稿覆盖当前发布快照，不保留版本历史 |
| 人工备份 | 发布前可复制大屏 |
| 视觉 | Studio 暖白低对比，画布默认专业深色主题 |
| 画布 | 固定逻辑尺寸，播放器按比例整体缩放并居中 |
| 数据 | 复用第一阶段数据集和原生数据库连接器 |
| 刷新 | 首次加载、手动刷新、页面级定时刷新 |
| 联动 | 只通过全局参数传播，不建设事件图 |
| 正式交付 | 独立播放和第三方嵌入 |
| 独立播放 | 可撤销的单屏播放密钥 |
| 嵌入 | 宿主鉴权、短期 Ticket、Origin 约束和可选 SDK |
| AI | 本阶段不实现，但协议和命令保持 AI 可生成 |

本规格对基础路线做两项阶段性收敛：

1. 第二阶段发布不实现不可变版本历史，只维护草稿和当前发布快照。
2. DuckDB 仍只保留为未来文件数据、Parquet 缓存和本地分析能力，不代理外部数据库查询。

## 5. 总体架构

```text
Editor Shell
    │ 写入
    ▼
DashboardDocument 草稿
    │
    ├── Component Runtime ──► Studio 草稿预览
    │
    └── Publish Service ──► 当前发布快照
                                │
                                ├── Standalone Player
                                └── Embed Player

Component Runtime
    ├── Component Registry
    ├── Data Runtime
    ├── Parameter Store
    ├── Theme Runtime
    └── Interaction Runtime
```

### 5.1 Document Core

负责：

- `DashboardDocument` 和组件实例模型。
- Schema 版本校验和规范化。
- 编辑器命令输入、输出和错误边界。
- 文档序列化和反序列化。

Document Core 不执行查询，也不渲染组件。

### 5.2 Component Runtime

负责：

- 根据组件类型从注册表加载实现。
- 统一处理组件渲染、主题、加载、空数据和错误状态。
- 在编辑预览、独立播放和嵌入播放中提供相同结果。
- 向 Data Runtime 提交结构化数据请求。
- 向 Interaction Runtime 发出标准交互事件。

组件不能直接读取编辑器 Store、数据库连接信息或宿主窗口状态。

### 5.3 Data Runtime

负责：

- 把数据绑定、`ChartSpec` 和全局参数转换为现有数据集查询请求。
- 对同一刷新周期内的相同请求去重。
- 管理请求取消、过期结果忽略和组件结果分发。
- 向组件提供统一的加载、成功、空数据和失败状态。

Data Runtime 只调用第一阶段的查询服务，不持有数据库驱动分支。

### 5.4 Editor Shell

负责：

- 画布选择、拖拽、缩放、对齐、层级和属性编辑。
- 文档命令、撤销重做和自动保存。
- 组件面板、图层面板和属性面板。
- 草稿全屏预览和发布入口。

Editor Shell 不包含任何图表专属渲染逻辑。

### 5.5 Publish Service

负责：

- 校验草稿文档和引用的数据集、资源与组件类型。
- 在事务中把完整草稿覆盖为当前发布快照。
- 记录发布时间，不生成版本历史。
- 保证发布失败时旧快照继续可用。

### 5.6 Player 与访问网关

负责：

- 根据访问模式验证管理员 Session、播放会话或 Embed Ticket。
- 只向正式播放器提供当前发布快照。
- 设置适合独立播放或嵌入播放的 CSP。
- 为 SDK 提供严格的 `postMessage` 协议。

## 6. DashboardDocument v1

顶层结构：

```json
{
  "schema_version": 1,
  "canvas": {
    "width": 1920,
    "height": 1080,
    "background": {}
  },
  "theme": {
    "id": "datapulse-dark",
    "tokens": {}
  },
  "refresh": {
    "mode": "interval",
    "interval_seconds": 30
  },
  "parameters": [],
  "components": []
}
```

每个组件实例包含：

```json
{
  "id": "component_uuid",
  "type": "builtin.line",
  "frame": {
    "x": 80,
    "y": 120,
    "width": 640,
    "height": 320,
    "z_index": 3
  },
  "state": {
    "locked": false,
    "hidden": false
  },
  "props": {},
  "style": {},
  "data_binding": {},
  "interactions": []
}
```

约束：

- 坐标和尺寸使用画布逻辑像素。
- 第二阶段不允许旋转和嵌套组件。
- `type` 必须存在于组件注册表。
- 颜色、字体和间距优先引用主题 Token，不在图表 Option 中散落硬编码值。
- 数据库凭据、原始连接字符串和 Embed 凭证不得进入文档。
- 未识别字段按 Schema 校验策略拒绝，不静默执行。

## 7. ChartSpec 与数据绑定

图表组件使用统一 `ChartSpec`：

```json
{
  "datasetId": "dataset_uuid",
  "dimensions": ["month"],
  "measures": [
    {
      "field": "amount",
      "aggregation": "sum"
    }
  ],
  "filters": [],
  "sort": [],
  "limit": 1000,
  "visual": {
    "type": "line"
  }
}
```

支持：

- 维度和指标。
- `count`、`sum`、`avg`、`min` 和 `max` 聚合。
- 字面量筛选和全局参数引用。
- 排序和返回数量限制。
- 与组件类型匹配的视觉属性。

后端把 `ChartSpec` 编译为参数化查询。前端和 AI 均不能通过 `ChartSpec` 注入原始 SQL、JavaScript 函数或 ECharts 回调函数。

文本、图片等无数据组件不创建查询。表格、KPI、进度和图表组件使用相同的数据结果协议。

## 8. 内置组件

第二阶段提供九类内置组件：

1. KPI 指标卡。
2. 文本。
3. 图片。
4. 表格。
5. 折线图和面积图。
6. 柱状图和横向条形图。
7. 饼图和环形图。
8. 进度条和仪表盘。
9. 基础 GeoJSON 地图。

组件通过内部注册表声明：

- 稳定类型 ID。
- 显示名称和图标。
- 属性 Schema。
- 数据能力。
- 默认尺寸和默认配置。
- 渲染实现。
- 可发出的标准交互事件。

本阶段固定注册协议，但不承诺第三方插件兼容性，也不加载任意外部代码。

## 9. 资源模型

图片和 GeoJSON 通过受控资源上传进入 DataPulse，不由服务端抓取任意外部 URL。

`ScreenAsset` 保存：

- 资源 ID。
- 资源类型：`image` 或 `geojson`。
- MIME 类型。
- 内容哈希。
- 文件大小。
- 本地持久化路径。
- 创建时间。

规则：

- 图片只接受 PNG、JPEG 和 WebP。
- GeoJSON 必须解析为合法 JSON，并限制为 `FeatureCollection`。
- 单个资源最大 5 MiB。
- 资源文件名由服务端生成，不能使用上传文件名作为磁盘路径。
- 删除被草稿或发布快照引用的资源返回冲突。
- 发布前必须验证引用资源存在。

地图组件引用 GeoJSON 资源 ID，并通过地区编码字段与数据集结果关联。

## 10. 编辑器体验

### 10.1 视觉结构

Studio 外壳延续 Notion 风格：

- 暖白背景。
- 低对比边框。
- 克制的阴影和工具栏。
- 清晰的文档式层级。

画布是独立主题空间：

- 默认使用专业深色大屏主题。
- 可以切换浅色和品牌主题。
- 播放器只显示画布，不显示 Studio 外壳。

编辑器布局：

- 左侧：组件面板和图层列表。
- 中间：画布、缩放和适配控制。
- 右侧：组件属性、数据、样式和交互。
- 顶部：保存状态、撤销重做、预览、复制和发布。

### 10.2 画布

- 提供常用尺寸预设和自定义宽高。
- 默认画布为 `1920 × 1080`。
- 使用绝对定位 DOM 容器。
- 支持网格和吸附。
- 支持多选、对齐、图层排序、锁定和隐藏。
- 支持编辑器缩放和适配窗口。
- 播放器按容器大小等比缩放整个逻辑画布并居中。
- 容器比例不一致时留边，不自动重排组件。

### 10.3 自动保存和冲突

- 文档变更经过 800 毫秒防抖后自动保存。
- UI 明确显示“未保存”“保存中”“已保存”和“保存失败”。
- 保存请求携带当前 `draft_revision`。
- 后端只在修订号匹配时写入，并原子增加修订号。
- 修订冲突时停止自动覆盖，提示用户重新载入最新草稿。
- 单管理员模式不建设协作合并。

### 10.4 撤销和重做

- 使用结构化编辑器命令维护当前会话历史。
- 撤销和重做不跨浏览器刷新持久化。
- 自动保存只保存当前文档，不保存历史命令。
- 后续 AI 修改必须转换为相同编辑器命令，并在执行前由用户确认。

## 11. 参数与联动

全局参数定义：

- 参数名。
- 数据类型。
- 默认值。
- 是否允许宿主动态修改。
- 可选的值域约束。

第二阶段的参数来源：

1. 文档中的默认值。
2. Embed Ticket 中的初始参数。
3. 宿主 SDK 对允许参数的修改。
4. 图表点击产生的参数更新。

本阶段不提供独立筛选器组件。

组件交互只允许“把点击值写入指定全局参数”。参数变化后，Data Runtime 只刷新引用了相关参数的查询。组件不能直接调用另一个组件的方法，也不能声明任意 JavaScript 动作。

## 12. 查询与刷新

刷新触发方式：

- 播放器首次加载。
- 用户手动刷新。
- 宿主 SDK 调用刷新。
- 全局参数发生变化。
- 页面级定时刷新。

定时刷新提供关闭、10 秒、30 秒、1 分钟和 5 分钟预设。文档只允许一个页面级刷新策略；本阶段不提供组件级独立定时器和服务器后台 Cron。

同一刷新周期内，规范化后的数据集、查询定义和参数完全相同时只执行一次查询，并把结果分发给所有调用组件。该去重只存在于当前页面内存中，不是跨请求查询缓存。

当新参数或新刷新周期开始时：

- 尽可能取消旧请求。
- 无法取消时，为请求分配代次并忽略过期结果。
- 旧结果不能覆盖较新的参数结果。

页面关闭后不继续查询外部数据库。

## 13. 草稿、发布与复制

`Screen` 元数据包含：

- `id`。
- `name`。
- `description`。
- `draft_document`。
- `draft_revision`。
- `published_document`，未发布时为空。
- `published_at`。
- `created_at`。
- `updated_at`。

### 13.1 发布

发布流程：

1. 自动保存或显式保存当前草稿。
2. 校验文档 Schema、组件类型、数据集和资源引用。
3. 提示“将覆盖当前线上版本，且无法直接回滚”。
4. 用户二次确认。
5. 在数据库事务内把完整草稿复制为当前发布快照。
6. 更新 `published_at`。

校验或事务失败时，现有发布快照保持不变。

### 13.2 复制

“复制大屏”创建新的大屏记录：

- 复制当前草稿文档。
- 生成新的大屏和组件 ID。
- 复用数据集和资源引用。
- 新大屏默认未发布。
- 名称追加“副本”，用户可以立即修改。

复制用于人工备份，不等同于版本历史。

## 14. 独立播放安全

管理员为已发布大屏生成播放密钥。密钥：

- 使用高熵随机值。
- 只在生成时显示明文。
- 数据库只保存哈希和版本。
- 绑定单张大屏。
- 可以重新生成；重新生成后旧密钥立即失效。

初次访问带播放密钥的地址时：

1. 服务端验证密钥哈希和大屏状态。
2. 设置 HttpOnly、SameSite=Lax，且在生产环境启用 Secure 的受限播放会话 Cookie。
3. Cookie 绑定大屏 ID 和播放密钥版本。
4. 重定向到不含密钥的 `/play/{screen_id}` 地址。
5. 后续请求同时验证播放会话和当前密钥版本。

播放会话采用 30 天滑动有效期；只要播放密钥版本仍然有效，播放器的正常查询请求就可以续期。管理员重新生成密钥后不能续期旧会话。

播放密钥被重新生成后，已有播放会话在下一次服务端请求时失效。

独立播放器设置：

- CSP `frame-ancestors 'none'`。
- 不返回 Studio 管理接口能力。
- 不包含数据源、SQL、凭据或管理信息。
- 只能读取绑定大屏的发布快照和查询其引用的数据集。

## 15. 安全嵌入

### 15.1 Embed API Key

DataPulse 提供一个宿主后端 API Key：

- 只在创建或重新生成时显示明文。
- 数据库只保存安全哈希和显示用后四位。
- 重新生成后旧 Key 立即失效。
- 只能用于申请 Embed Ticket，不能调用 Studio 管理接口。

### 15.2 Embed Ticket

宿主后端完成用户认证和业务授权后，使用 API Key 请求 Ticket。

Ticket 至少包含：

- Ticket ID。
- 大屏 ID。
- 签发时间和过期时间。
- 允许的宿主 Origin。
- 初始全局参数。
- 允许 SDK 修改的参数名。

Ticket 使用服务器配置的 `DATAPULSE_SIGNING_KEY` 签名。生产环境启用嵌入功能时该配置为必需项。Ticket 默认有效期 1 小时，最大 8 小时。Ticket 过期后播放器停止发起新查询，并通过 SDK 发送 `error`；宿主重新申请 Ticket 并重载 iframe。

iframe 首次加载时通过 URL 携带 Ticket。嵌入页必须：

- 设置 `Cache-Control: no-store` 和 `Referrer-Policy: no-referrer`。
- 在服务端访问日志中删除 Ticket 查询参数。
- 验证 Ticket 后立即用 `history.replaceState` 从地址栏移除 Ticket。
- 只在当前 iframe 的内存中保留 Ticket，并在查询请求中作为受限 Bearer 凭证发送。
- 页面刷新或 Ticket 过期后要求宿主重新加载新的 Ticket。

Ticket 不进入 Cookie、Local Storage 或 Session Storage。

### 15.3 CSP 和通信

嵌入响应根据 Ticket 的允许 Origin 设置 CSP `frame-ancestors`。

SDK 和 iframe 使用 `postMessage`，双方必须：

- 使用明确的目标 Origin，不使用 `*`。
- 校验 `event.origin`。
- 校验消息协议版本、消息类型和实例 ID。
- 拒绝未声明字段和不允许的参数名。

播放器只接受 Ticket 中允许动态修改的参数。参数值仍需通过类型和值域校验。

### 15.4 轻量 JavaScript SDK

SDK 是可选的浏览器辅助库，宿主 Java 后端只负责申请 Ticket。

SDK 提供：

- `ready`。
- `refresh()`。
- `setParameters()`。
- `getParameters()`。
- `fullscreen()`。
- `error`。

不使用 SDK 时，宿主仍可直接创建带有效 Ticket 的 iframe。

第二阶段 SDK 不提供截图、下载、组件点击回调和 AI 问答。

## 16. 错误处理

错误按组件和访问层隔离。

组件状态：

- 加载中。
- 成功。
- 无数据。
- 配置错误。
- 查询失败。
- 查询超时。

规则：

- 单个组件失败不能导致整张大屏白屏。
- Studio 预览显示稳定错误码、请求 ID 和可诊断信息。
- 正式播放器只显示安全、简洁的错误信息。
- 服务器日志和查询诊断保留具体原因。
- SQL、数据库地址、参数值、凭据和堆栈不返回给播放器。
- Embed Ticket、播放密钥和 API Key 不写入应用日志。
- SDK 通过 `error` 事件报告访问过期、参数拒绝和播放器级失败。

## 17. AI 兼容边界

本阶段不实现 AI UI 或模型调用，但必须保证：

- AI 可以生成合法 `ChartSpec`。
- AI 可以生成新的 `DashboardDocument` 草稿。
- AI 修改现有大屏时使用结构化编辑器命令。
- AI 不能直接生成或执行 JavaScript。
- AI 不能绕过数据集和安全查询层。
- AI 不能未经管理员确认直接发布。
- 组件属性 Schema、主题 Token 和命令协议可以供未来 AI 获取。

## 19. 完成标准

第二阶段在满足以下条件时完成：

1. 管理员可以创建、复制、编辑和删除大屏。
2. 当前 21 类内置组件通过统一运行时在编辑预览和正式播放器中一致渲染。
3. 画布编辑、自动保存、修订冲突和撤销重做可用。
4. 数据集可以通过 `ChartSpec` 绑定到组件。
5. 全局参数、点击联动、首次加载、手动刷新和页面级定时刷新可用。
6. 发布会经二次确认覆盖当前快照，失败不会破坏旧快照。
7. 独立播放可以通过可撤销播放密钥长期运行。
8. 第三方系统可以通过 API Key、Embed Ticket 和 iframe 安全嵌入。
9. JavaScript SDK 可以刷新、读写允许参数、全屏并接收错误。
10. 单组件错误不会破坏整张大屏，正式播放器不会泄露敏感信息。
11. 单元、集成、端到端、安全和截图回归测试覆盖核心流程。
