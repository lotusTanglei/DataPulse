# 第四阶段：多用户与资源协作

状态：依据 2026-09-21 执行请求确定的首版实现设计。文中新增语义为本轮设计决策，不冒充历史已确认需求。

## 范围与选型

采用本地账号、固定系统角色与逐资源授权，沿用 Session/CSRF。与仅增加全局角色相比，它能隔离资源；与组织树、行列权限和实时协同相比，它保留私有部署的简单性。宿主观看者继续使用原有 Ticket/显示密钥。

角色为 `admin`、`editor`、`viewer`。admin 管理用户、授权、发布入口、系统设置、生态安装和所有资源；editor 可创建资源并修改自己拥有或获写授权的资源；viewer 只可读取获授权的资源。共享权限为 `read`、`write`、`publish`，发布不隐含管理账号或系统设置。资源拥有者可维护本资源授权。viewer 的角色上限始终只读，授权不能提升角色上限。

资源类别覆盖 datasource、dataset、file、asset、screen。系统设置、供应商凭据、插件安装、备份与宿主 API Key 管理由 admin 专有。新账号默认不获得历史资源；已有管理员迁移为 admin，历史资源归其所有。新建资源登记归属。未知管理路由默认拒绝非 admin，新增端点必须显式声明策略。

## 身份生命周期

复用 admin_account/admin_session，追加 role、active 等必要字段；新账号使用随机 ID。用户名唯一、密码沿用现有哈希和最短长度。账号创建、角色/启用状态调整和管理员重置密码只允许 admin，禁止禁用或降级最后一个有效管理员。角色变更、停用和密码重置撤销已有会话，后续请求实时检查账号状态。响应不包含密码哈希。

提供 `/api/admin/users` 列表/创建、`/{id}` 更新，以及受保护的授权和审计接口。`/api/auth/session` 返回用户 ID、用户名与角色，旧客户端仍可读取 username。

## 授权边界

服务端统一决策，覆盖列表过滤、详情、查询/预览、写入、删除、资产字节、复制、发布、显示密钥和访问策略。非可见资源与不存在资源使用一致响应，不能通过资源存在性探测泄漏。

创建/修改数据集、屏幕和 AI 请求时检查所有引用：数据源、文件、数据集和媒体必须具备对应读取权限；不能通过可写大屏绑定其他人的数据。查询与预览重新校验引用权限；撤销后不得凭缓存继续查询。共享屏幕不自动共享任意数据集接口，管理者需显式授权依赖。发布播放器保持发布快照与 Ticket 授权语义。

共享记录写入专用权限表，账号/资源标识及权限受服务端合同约束。权限变更审计只保存动作、资源标识、操作者、时间和 request ID，不保存凭据或查询数据。

## 协作与界面

复用 draft_revision 与 expected_revision 的原子保存/发布及 409 冲突，保留停止自动重试、提示重新加载的现有流程。补充两个不同账号编辑同一资源的回归。系统设置增加用户管理；资源授权界面提供资源类型/标识、用户与授权选择及撤销。界面根据角色提示能力，服务端负责最终鉴权。

## 验收

覆盖旧库迁移、创建/登录/停用/重置/角色变更、最后管理员保护、匿名与 CSRF、跨用户列表与详情、引用越权、发布和下载、缓存后的撤销、并发保存冲突以及审计脱敏。数据源凭据仍不回显，宿主与播放链路不引入 Studio 会话。
