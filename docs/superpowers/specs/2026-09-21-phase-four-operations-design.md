# 第四阶段：备份恢复与运维

状态：2026-09-21 首版实现设计。

## 备份恢复

提供管理员运维 CLI，优先支持当前默认 SQLite 单实例，并对 PostgreSQL 明确使用数据库原生一致性备份和独立恢复手册；不把不支持的拓扑伪装成自动备份成功。生产备份在 API、worker 与文件写入均停止的维护窗口运行。数据库使用 SQLite backup API 生成一致副本，文件从显式管理的路径收集，拒绝符号链接和目录逃逸。

归档包括版本清单、数据库、上传文件/媒体、插件依赖和每个成员的 SHA-256，不包括 .env、密钥文件、浏览器凭据或临时日志。凭据密文可备份，恢复时需通过独立受控途径提供原 master/signing key；不要把明文钥匙装入归档。记录加密依赖指纹而不泄漏密钥。

校验在解包前验证成员名、数量、压缩后/展开大小、校验和、数据库完整性及版本兼容。恢复先在新目录 staging 完成数据库和文件引用检查并重映射存储绝对路径，验证后再原子落地到空目标目录；默认拒绝覆盖现有实例。失效/中断保留目标数据，不进行隐含 destructive replace。旧会话和一次性初始化凭据不能因恢复重新激活。

CLI 提供 create、verify、restore、inspect；输出不包含秘钥。提供干净实例演练脚本和操作手册；实际测试包含资产、文件、已发布文档、插件依赖和凭据解密，以及重启后查询/播放能力。

## 运维与安全

复用 speech worker、持久指标、Prometheus 和告警规则。检查跨进程领取、重启恢复、配额原子性、资源清理和日志脱敏；仅对证实缺口加实现。扫描器使用明确配置的本地可执行程序或受控服务适配，超时、退出码和不可用时采取 fail-closed；文件/媒体在持久化发布前扫描。外部进程处理限制时间和资源，真实部署隔离由部署手册规定并验收。

所有新运维 API 限 admin；日志记录动作、稳定错误、耗时和 request ID，避免正文、URL query 和高基数标签。容量基线沿用路线的 2 核/4GB、50 观看连接、播放器首屏约 3 秒及查询限制，区分依赖服务耗时。

## 环境门禁

`docs/PHASE_FOUR_TARGET_ENVIRONMENT.md` 八项门禁保持编号与通过标准。本地 Docker、mock、软件 4K 和短时预检仅记录预检结果。没有组织设备、真实供应商测试账户、目标网络和 8 小时执行条件时如实阻塞，继续实施其他功能和演练工具。外部验收条件尚未获得，不标为通过。
