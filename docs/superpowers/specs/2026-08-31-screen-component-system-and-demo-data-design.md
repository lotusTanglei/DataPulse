# DataPulse 大屏设计器组件体系、视觉系统与演示数据设计

日期：2026-08-31
状态：已确认，核心能力已实现；固定数据编辑器与播放质量增强待后续迭代
适用范围：产品第二阶段（数据理解与融合创作）的 DataPulse 大屏设计器与统一播放运行时；数字人播报属于产品第三阶段
参考方向：[Vue + ECharts 大屏可视化](https://blog.csdn.net/xiaod00000000000/article/details/136640984)

## 1. 背景与问题

DataPulse 当前已经具备固定画布、组件拖拽、图层管理、数据集绑定、草稿预览、发布播放和嵌入播放能力，但大屏设计器仍存在两个直接影响使用的问题：

1. 内置组件数量和类型不足，无法覆盖常见的数据展示结构。
2. 组件默认表现接近普通后台页面，缺少完整的大屏视觉层级、面板结构、图表皮肤和状态表现。

此外，设计阶段可能还没有数据源或数据集。没有数据时，组件只能显示“暂无数据”或空白图表，用户无法判断布局、颜色、字号、图表比例和最终播放效果。

本设计解决的是“大屏设计器的通用创作能力”，不绑定生产运营、交通监控、园区治理或任何单一业务行业。具体行业数据应由数据集、静态数据或用户自己的模板提供。

博客只作为视觉语言参考，不直接复制其中的图片、代码、业务文案或具体页面。参考重点是深色画布、高信息密度、中心视觉、分栏组织、装饰面板、发光图表、环形指标和状态列表。

## 2. 设计目标

### 2.1 目标

- 形成一套可复用的专业大屏视觉系统，而不是为某一套模板编写孤立 CSS。
- 以设计启动时的九类组件为基线，扩展为当前 21 类覆盖文本、装饰、指标、图表、排行、列表和地图的通用组件体系。
- 所有组件都具备清晰的默认样式、可配置样式和完整运行时状态。
- 在没有数据源和数据集时，用户可以给任意数据组件加载可重复的模拟数据。
- 编辑器、草稿预览、独立播放和嵌入播放复用同一套组件实现和数据结果协议。
- 保留当前 `DashboardDocument`、`ChartSpec`、编辑命令、自动保存和发布模型的兼容性。

### 2.2 非目标

- 不把产品定位为某个行业的专用大屏。
- 不在本设计中实现 3D 数字孪生、复杂 WebGL 场景或完整 GIS 平台。
- 不实现任意 JavaScript 组件、任意 HTML 注入或用户上传可执行代码。
- 不实现组件之间的任意事件连线；第一阶段仍使用全局参数联动。
- 不在产品第二阶段实现模板市场、组件市场、多页编排和多人协作。

## 3. 现状与兼容约束

### 3.1 当前实现

- 设计启动时组件注册表只有九类；当前 `apps/web/src/features/runtime/registry.ts` 已定义 21 类内置组件，完整清单见第 6.1 节。
- `ComponentInstance` 已经包含 `frame`、`props`、`style`、`data_binding`、`interactions` 和 `state`。
- `data_binding` 当前是开放字典，图表通常使用其中的 `chart_spec`。
- `ScreenRuntime` 负责画布缩放、页面刷新、参数变化和组件运行时状态，见 `apps/web/src/features/runtime/ScreenRuntime.vue`。
- `DataRuntime` 负责请求去重、请求取消、刷新代次和组件级结果状态，见 `apps/web/src/features/runtime/dataRuntime.ts`。
- 当前样式控制主要是背景色、文字色、边框色、边框宽度、圆角和透明度；图表视觉配置集中在 `chartOptions.ts`。
- 当前模板创建后大多数组件没有数据绑定，因此只能呈现空状态。

### 3.2 兼容原则

- 逻辑画布默认仍为 `1920 × 1080`，坐标和尺寸继续使用画布逻辑像素。
- 已有无 `source` 字段且包含 `chart_spec` 的绑定继续解释为真实数据集绑定。
- 已有组件类型和旧版 `props` 保持可读取；新增属性使用默认值补全。
- 新组件类型必须经过注册表校验，未知类型继续使用组件级降级状态。
- 静态数据和模拟数据均转换为现有 `QueryResult` 后交给组件，不为每种数据模式创建不同的组件接口。
- 发布和嵌入协议不因模拟数据增加数据库权限或新的外部请求。

## 5. 大屏视觉系统

### 5.1 视觉原则

大屏视觉采用“内容优先的科技指挥中心”语言：

- 深色画布提供对比度，组件内部使用层级明确的面板和内容区。
- 视觉焦点由标题、核心指标或中心图表建立，不能把所有组件做成相同权重的卡片。
- 装饰用于表达层级和状态，不用于填充空白。
- 颜色表达业务语义，不能只使用一套蓝色，也不能让每个组件都发光。
- 默认保证远距离可读性，图表标注、数字、状态和异常信息优先于装饰。
- 设计语言参考博客中的线框、角标、扫描线、网格和轻微光效，但默认保持克制；用户可以关闭装饰层。

### 5.2 画布结构

默认画布结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 页面标题 / 副标题 / 时间 / 数据状态                          │ 72 px
├──────────────────────────────────────────────────────────────┤
│ 核心指标区 / 数字 / 同比 / 状态                               │ 140 px
├──────────────┬───────────────────────┬───────────────────────┤
│ 左侧分析栏   │ 中央主视觉区          │ 右侧状态与告警栏      │
│ 趋势/排行    │ 主图/地图/核心指标    │ 列表/进度/状态        │
├──────────────┴───────────────────────┴───────────────────────┤
│ 明细表 / 时间线 / 事件流 / 更新时间                           │
└──────────────────────────────────────────────────────────────┘
```

这是推荐的组合方式，不是固定模板。组件仍然可以自由拖拽，但模板和自动布局应优先使用以下约束：

- 内容安全边距 32–48px。
- 面板之间 16–24px 间距。
- 重要内容占据较大面积，辅助内容使用紧凑面板。
- 一屏同时使用的主要颜色不超过 6 个。
- 相邻面板保持统一的标题位置、内边距和底部基线。

### 5.3 主题令牌

主题令牌由画布继承，组件默认读取令牌，组件级样式只覆盖显式修改的属性。

```text
canvas_background       画布背景色
canvas_background_image 受控背景资源
canvas_overlay           背景叠加层透明度
panel_background         面板背景色
panel_background_alt     面板第二层背景色
panel_border              面板边框色
panel_frame               面板装饰类型
panel_radius              面板圆角
text_primary              主文本
text_secondary            次文本
text_muted                辅助文本
accent                    主强调色
info                      信息色
success                   正常色
warning                   预警色
danger                    异常色
chart_colors              图表序列色板
chart_grid                图表网格线
chart_axis                图表坐标轴
font_family               大屏字体栈
```

推荐默认深色主题：

```text
canvas_background: #071522
panel_background: #0b1b2b
panel_background_alt: #10253a
panel_border: #1b4160
text_primary: #edf7ff
text_secondary: #9ab3c8
text_muted: #638198
accent: #26d9c1
info: #3b8df4
success: #43d17d
warning: #f3b638
danger: #f16d75
chart_colors: [#26d9c1, #3b8df4, #8a9ff0, #f3b638, #f16d75, #a5d85b]
```

同时提供浅色主题和用户自定义主题，但浅色主题不是简单反转颜色，需要重新定义面板、网格线和状态色的对比度。

### 5.4 面板框架

面板增加 `panel_frame` 视觉选项：

- `plain`：只有底色和细边框，适合表格和辅助内容。
- `line`：顶部标题线和底部基线，适合普通图表。
- `corner`：四角装饰线，适合重点指标和告警。
- `tech`：短横线、角标和低透明度网格，适合中心主视觉。
- `glass`：半透明面板和背景透出，默认不开启，仅在背景图场景使用。

面板装饰使用 CSS/SVG 原生图形实现，不依赖外部图片，不将装饰做成不可编辑的整屏背景。所有面板框架必须支持关闭，确保数据可读性优先。

### 5.5 播放与缩放

- 播放器继续按画布整体 `contain` 缩放，非 16:9 容器保留留边。
- 编辑器初始缩放使用“适应画布”，而不是固定 50%。
- 4K 播放优先使用 SVG 图表渲染或按设备像素比重绘，避免 CSS 放大导致文字和线条模糊。
- 播放端隐藏网格、选区、图层、组件名称和编辑器状态条。
- 动画默认只播放一次或按刷新触发，禁止无意义的无限循环；遵循 `prefers-reduced-motion`。

### 6.2 核心组件实现范围

为了快速解决“样式过于简单”和“无法无数据演示”两个问题，核心实现覆盖：

- 面板
- 数字翻牌
- 仪表盘
- 排行榜
- 告警列表
- 雷达图
- 增强版折线、柱状、饼图、KPI、进度、表格

分割线、状态矩阵、热力图、散点图、漏斗图、时间线和内置地图演示资源也已纳入当前实现。固定数据的表格化编辑、批量样式修改、多格式导入和高 DPI 播放优化仍作为后续迭代，不影响当前设计器使用静态 JSON、确定性模拟数据完成设计演示。

## 7. 组件通用协议

### 7.1 组件定义

组件注册表中的定义需要从当前的类型、默认尺寸、默认 Props 和渲染组件扩展为可描述的编辑元数据：

```ts
interface ComponentDefinition {
  type: BuiltinComponentType;
  label: string;
  category: ComponentCategory;
  defaultFrame: { width: number; height: number };
  defaultProps: Record<string, JsonValue>;
  defaultStyle: Record<string, JsonValue>;
  dataCapability: DataCapability;
  demoDataKind: DemoDataKind;
  propertyGroups?: PropertyGroup[];
  component: Component;
}
```

属性元数据用于生成属性面板，避免每新增一个组件都在 `InspectorPanel.vue` 中加入一组特殊判断。组件实现仍然是 Vue 组件，元数据只描述可编辑能力。

### 7.2 通用 Props

所有组件可以选择支持以下通用字段：

```text
title             面板或图表标题
subtitle          副标题
unit              数值单位
empty_text        空数据文本
loading_variant   加载状态样式
error_text        错误状态覆盖文本
show_legend       是否显示图例
show_value        是否显示数值
animation         动画开关和持续时间
```

### 7.3 通用样式

```text
surface_variant   transparent / solid / translucent / glass
frame_variant     plain / line / corner / tech / glass
padding           组件内边距
title_color       标题颜色或主题令牌
accent_color      强调色或主题令牌
border_width      边框宽度
border_radius     圆角
opacity           透明度
```

样式值支持主题令牌引用和显式颜色。默认配置只保存令牌或默认值，不在每个模板组件中复制完整色板。

## 8. 组件详细设计

### 8.1 面板与装饰

#### 面板

面板是布局和装饰组件，不绑定数据。它负责提供背景、标题栏、边角装饰、网格和内容承载区域，但不嵌套其他组件。组件覆盖关系仍由画布 z-index 控制。

配置项：

- 标题、副标题、标题对齐方式；
- `plain / line / corner / tech / glass` 框架；
- 背景透明度、边框和强调色；
- 顶部装饰线长度、角标开关、背景网格开关。

#### 数字翻牌

用于展示单个重要数值，不要求数据集必须存在。支持数字格式、前缀、后缀、小数位、变化值、变化方向和动画开关。

### 8.2 指标与状态

#### KPI

提供 `hero / standard / compact` 三种密度：

- `hero`：页面主指标，大数字、单位和趋势变化。
- `standard`：常规指标卡，适合一行 3–5 个。
- `compact`：侧栏指标，适合和列表或告警并列。

支持主值、目标值、变化值、变化百分比、状态色、图标和迷你趋势。没有变化数据时不显示假箭头和假百分比。

#### 进度与仪表盘

进度支持横向、分段和环形；仪表盘支持半圆、整圆和阈值分区。阈值颜色必须同时配合文字或数值，不得只依靠颜色表达状态。

### 8.3 图表

所有图表统一处理：标题、单位、图例、坐标轴、网格线、Tooltip、空状态、动画、主题色和高 DPI 渲染。

#### 折线图

- 折线、面积、阶梯和目标线变体；
- 支持单序列和多序列；
- 支持平滑曲线、末端标签、数据点和区域填充；
- 默认隐藏冗余坐标轴边框，保留足够的水平网格线；
- 小尺寸组件自动减少坐标标签和图例。

#### 柱状图

- 横向排行和纵向对比；
- 分组、堆叠和目标对比；
- 支持数值标签、条形圆角和强调 Top N；
- 横向排行优先用于分类名称较长的场景。

#### 饼图、环图、雷达图、热力图、散点图和漏斗图

- 饼图分类超过 6 个时合并为“其他”或提示用户切换为排行榜；
- 环图中间可显示合计，但不强制添加没有业务意义的总数；
- 雷达图必须有字段名称和最大值配置，避免轴含义不清；
- 热力图需要维度、时间或分类轴，空数据时显示明确的无数据状态；
- 散点图支持异常点强调和 Tooltip，但不默认添加回归线；
- 漏斗图显示每阶段数值和转化率，阶段数过多时自动压缩标签。

### 8.4 列表与分析

#### 表格

支持普通表格、紧凑表格、状态表格三种变体。表头、行高、斑马纹、排序箭头和状态标记均使用主题令牌。表格必须保留空、加载、错误和截断状态。

#### 排行榜

数据结构为名次、名称、数值、变化值，可选择：

- 纯名次列表；
- 横向条形排行；
- Top 3 强调排行。

#### 告警列表

数据结构为等级、标题、详情、时间、状态。等级同时用颜色、图标和文本表达。支持滚动展示，但不默认自动滚动；自动轮播属于后续播放设置。

#### 时间线与状态矩阵

时间线用于事件顺序和任务阶段；状态矩阵用于多个对象的在线、运行、暂停、故障和离线状态。两者都应支持数据行数量限制和紧凑模式。

### 8.5 地图

地图继续使用受控 GeoJSON 资源 ID，不允许组件直接加载外部 URL。增强内容包括：

- 区域着色和数值 Tooltip；
- 标记点和聚合点；
- 图例、最大最小值和缺失区域状态；
- 内置示例 GeoJSON 资源，便于无数据演示；
- 地图组件没有合法资源时显示资源配置提示，不显示黑色空块。

## 9. 组件运行时状态

所有数据组件统一使用以下状态：

| 状态 | 编辑器表现 | 播放器表现 |
| --- | --- | --- |
| 未绑定 | 网格占位、组件类型、添加演示数据入口 | 使用配置的空状态 |
| 模拟数据 | 角标显示“演示数据” | 可配置是否显示轻量演示标记 |
| 静态数据 | 正常图表，数据面板显示“固定数据” | 正常展示，不请求接口 |
| 数据集 | 正常图表，显示数据集名称 | 请求真实数据 |
| 加载中 | 内容骨架或低干扰加载动画 | 不闪烁，保留上一份成功结果 |
| 空数据 | 图标、短文本、数据模式提示 | 只显示短文本，不泄露内部信息 |
| 查询失败 | 组件右下角错误标记，可重试 | 组件内局部错误，不影响整屏 |
| 类型错误 | 编辑器显示配置错误 | 显示稳定的组件降级状态 |

加载期间如果已有成功结果，保留旧结果并在角落显示更新状态；避免整块图表闪成空白。

## 10. 演示数据设计

### 10.1 三种数据模式

数据面板使用分段选择：

```text
数据集       连接真实数据集，使用现有 ChartSpec 查询
固定数据     用户输入并保存一份静态表格，不请求接口
演示数据     按组件类型生成确定性的假数据，用于设计和预览
```

旧绑定如果存在 `chart_spec`，自动归类为“数据集”。没有绑定的组件默认显示“添加演示数据”和“选择数据集”两个入口。

### 10.2 数据结构

真实数据集继续使用现有 `chart_spec`。固定数据和演示数据使用统一的存储结构：

```json
{
  "source": "static",
  "static_data": {
    "schema_version": 1,
    "columns": [
      { "name": "类别", "data_type": "string" },
      { "name": "数值", "data_type": "number" }
    ],
    "rows": [["A", 120], ["B", 86]]
  }
}
```

演示数据使用确定性配置：

```json
{
  "source": "mock",
  "mock_data": {
    "schema_version": 1,
    "preset": "time_series",
    "seed": 42,
    "row_count": 12,
    "series_count": 2,
    "value_min": 0,
    "value_max": 100,
    "trend": "up"
  }
}
```

运行时将 `static_data` 直接包装为 `QueryResult`；将 `mock_data` 用纯前端、无网络的确定性生成器转换为同样的 `QueryResult`。模拟数据不使用 `Math.random()`，相同的 `seed` 和配置必须得到相同结果。

### 10.3 演示数据预设

预设按数据能力匹配：

| 数据能力 | 默认预设 | 结果结构 |
| --- | --- | --- |
| `single` | 单指标 | 一列数值、一行数据 |
| `series` | 时间趋势 | 时间维度 + 1–3 个数值序列 |
| `table` | 明细表 | 3–8 列、8–20 行 |
| `geo` | 区域分布 | 区域编码 + 名称 + 数值 |
| 排行榜 | 分类排行 | 名称 + 数值 + 变化值 |
| 告警列表 | 状态事件 | 等级 + 标题 + 时间 + 状态 |
| 雷达图 | 多维能力 | 分类 + 多个指标 |
| 热力图 | 时间分类 | 两个维度 + 数值 |

用户可以调整行数、序列数、数值范围、趋势方向、类别数量和 seed。生成后点击“固定数据”可以将结果物化为 `static_data`，从而允许手工编辑。

### 10.4 固定数据编辑器

固定数据编辑器的目标形态提供：

- 单元格编辑；
- 增加、删除和复制行；
- 增加、删除和重命名列；
- 字段类型切换：字符串、整数、数字、日期、时间；
- 粘贴 Excel/TSV 表格；
- 导入 CSV 和简单 JSON 数组；
- 清空数据和恢复当前演示数据；
- 维度、指标、系列和 Tooltip 字段映射；
- 右侧实时图表预览。

当前实现提供 JSON 固定数据录入，接受一层对象数组或 `{ columns, rows }` 二维数组，并将标量字段转换为表格列。公式、跨表关联、SQL、脚本、任意对象嵌套、CSV/TSV 导入和表格化编辑器属于后续迭代。

### 10.5 数据限制与安全

- 单个组件最多 20 列、500 行。
- 单个大屏内固定和演示数据合计建议不超过 1MB。
- 每行字段数量必须与列数量一致；缺失值统一为 `null`。
- 只接受 JSON 标量，不接受 HTML、脚本、函数和外部资源地址。
- 粘贴内容需要经过字段类型校验和长度限制。
- 模拟数据和固定数据不进入数据库查询接口，不增加数据库权限。
- 发布前显示“包含演示数据”的数量；用户确认后才允许发布含模拟数据的大屏。
- 播放端可配置是否显示轻量“演示数据”标记，默认在草稿预览显示，正式播放隐藏。

## 11. 属性面板交互

### 11.1 数据面板

没有绑定时显示三个主要操作：

```text
使用数据集     进入现有数据集绑定流程
使用演示数据   根据组件能力生成预设数据
录入固定数据   打开空表格编辑器
```

有绑定时显示：

- 当前来源和状态；
- 数据预览；
- 字段映射；
- 数据模式转换；
- 重新生成演示数据；
- 固定数据编辑；
- 清除绑定。

每次生成或修改后先更新本地编辑历史，再由统一数据运行时刷新组件。无需点击“刷新数据”才能看到本地演示数据。

### 11.2 样式面板

样式面板分为“主题继承”和“组件覆盖”两层：

```text
主题
  当前主题 / 快速切换 / 画布背景 / 全局色板

面板
  框架类型 / 底色 / 透明度 / 边框 / 圆角 / 内边距

文字
  字体 / 字号 / 字重 / 颜色 / 对齐 / 行高

图表
  色板 / 网格 / 坐标轴 / 图例 / Tooltip / 标签 / 动画

状态
  加载样式 / 空数据样式 / 错误样式 / 演示数据标记
```

点击“恢复主题默认值”只清除组件覆盖，不影响文档其他组件。批量选中多个同类型组件时，允许批量修改共同支持的属性。

### 11.3 组件库

组件库使用分类和视觉预览，而不是只显示“+ 文字”。每个组件项展示：

- 组件图标；
- 组件名称；
- 简短视觉缩略图；
- 是否支持数据；
- 点击后使用默认主题样式创建。

模板选择器同样复用运行时缩略渲染，模板必须带有内置演示数据，打开模板选择器即可看到实际图表，而不是只有模板名称和说明。

## 12. 运行时架构调整

```text
ComponentInstance.data_binding
              │
              ▼
        Data Runtime
        ┌───────────────┐
        │ source=dataset│──► 现有查询 API
        │ source=static │──► 静态结果适配器
        │ source=mock   │──► 确定性模拟数据生成器
        └───────────────┘
              │
              ▼
          QueryResult
              │
              ▼
       ComponentHost / 组件
```

实现要求：

- `DataRuntime` 的 `load()` 在请求开始前识别来源模式。
- `static` 和 `mock` 不创建 `AbortController`，但仍写入组件的 loading/success/error 状态。
- 相同绑定在同一刷新周期内继续去重；静态和模拟数据的 key 包含完整数据配置与 seed。
- 页面定时刷新只重新计算模拟数据或复用固定数据，不发起网络请求。
- 参数联动只作用于包含真实数据集查询的组件；静态和模拟数据组件不因参数变化伪造查询结果。
- 编辑器画布和正式播放器都使用同一份适配器，避免设计预览和播放表现不一致。

## 13. 发布、复制与导入行为

### 13.1 发布

发布校验增加：

- 新组件类型是否存在；
- 数据列和行是否符合限制；
- `mock_data` 是否为合法预设；
- 地图资源是否为受控资源；
- 主题令牌是否为允许的标量值；
- 文档是否超过大小限制。

含演示数据时，发布确认窗口显示：

```text
此大屏包含 5 个演示数据组件。
演示数据不会访问数据源，适合展示和联调。
```

用户确认后可以发布；复制大屏时完整复制固定数据和演示数据，并保留新的组件 ID。

### 13.2 导入与升级

- 旧版文档无需迁移即可打开。
- 第一次保存时可以进行内存规范化，但不强制立即升级 Schema 版本。
- 新增 `source`、`static_data` 和 `mock_data` 属于 `data_binding` 扩展，初始仍保持 `DashboardDocument` schema version 1。
- 如果后续需要服务端严格校验复杂数据结构，再升级为 DashboardDocument schema version 2，并提供 v1 到 v2 的纯函数迁移器。

## 15. 测试设计

### 15.1 单元测试

- 每个组件定义包含默认尺寸、默认 Props、样式默认值和数据能力。
- 模拟数据相同 seed 生成相同结果，不同 seed 产生可区分结果。
- 静态数据能转换为合法 `QueryResult`。
- 非法列类型、行长度、行数和文档大小会被拒绝。
- 旧版 `chart_spec` 绑定继续走真实查询路径。
- 静态和模拟绑定不会调用查询 API。
- 组件在未绑定、加载、空数据、错误和成功状态下都有稳定 DOM 标记。

### 15.2 集成测试

- 新建空大屏后添加每类组件，均能显示默认样式。
- 没有数据源时，所有支持数据的组件都可以加载模拟数据。
- 编辑、撤销、重做、自动保存和重新加载后，演示数据配置保持一致。
- 模拟数据转换为固定数据后可以编辑并保存。
- 混合真实数据、固定数据和模拟数据的页面可以同时播放。
- 页面定时刷新不为固定和模拟数据发起网络请求。
- 发布含演示数据的大屏时出现确认提示，发布后仍能正常播放。

### 15.3 视觉回归

至少覆盖：

- 默认深色主题；
- 浅色主题；
- 用户自定义主题；
- 1920 × 1080 播放；
- 1366 × 768 留边播放；
- 4K 播放清晰度；
- 320px 以上编辑器窄容器；
- 含错误组件但其他组件正常播放；
- 全部组件带模拟数据的模板缩略图和正式预览。

## 16. 验收标准

1. 组件库已从设计时九类扩展到当前 21 类，超过至少 15 类的目标，并包含面板、数字翻牌、仪表盘、排行榜、告警列表和雷达图。
2. 创建任意新组件后，不再出现默认白底、黑字、空图表或无标题的普通后台样式。
3. 每类数据组件都可以在没有数据源和数据集时使用演示数据展示。
4. 相同演示数据配置在编辑器、草稿预览、独立播放和嵌入播放中的结果一致。
5. 模拟数据不会请求数据库接口，固定数据不会创建网络查询。
6. 主题可以统一修改背景、面板、文本、状态色和图表色板，组件可以单独覆盖。
7. 组件拥有清晰的未绑定、加载、空数据、错误和成功状态。
8. 模板选择器显示真实的带数据视觉预览。
9. 现有数据集绑定、大屏发布、播放密钥和嵌入票据流程保持兼容。
10. 单个组件错误不会导致整张大屏白屏，播放端不泄露内部查询错误信息。

## 17. 最终建议

产品第二阶段不继续堆叠模板数量，也不先做某个行业的完整大屏。当前已完成“主题 Token + 统一面板框架 + 现有组件皮肤 + 演示数据运行时”四个基础能力；后续增强应以实际验收缺口为依据。

这样可以让任何行业模板都共享同一套视觉系统，也能让用户在没有真实数据的情况下完成布局、样式、交互和播放验证。博客中的科技大屏风格应作为可配置主题语言，而不是写死在某一个业务模板里。
