# DataPulse plugin SDK

Plugins export `definePlugin({ apiVersion: 1, components: { [type]: renderer } })` as the module default. Each renderer implements `mount(element, context)`, returning `update(context)` and `destroy()`. The context provides `instanceId`, validated `props`, a controlled `QueryResult` or `null`, `loading`, `error`, `theme`, and an `AbortSignal`. Dispose listeners, timers and DOM on `destroy`; honor cancellation before asynchronous work mutates DOM.

An optional synchronous `migrate(props, fromVersion)` returns complete replacement props for explicit draft migration. It is never called automatically on install or publication. Each document pins exact `{id, version}` dependencies and gets its own component registry. In the editor's installed plugin library, choose **草稿切换至 VERSION** to load the target module and migrate every component owned by that plugin. Each call receives a detached props copy. All returned values must be JSON objects satisfying the target property schema; without `migrate`, the existing props must already satisfy that schema. A removed renderer, thrown error, invalid props, or intervening draft edit rejects the entire operation. Success changes props and the pinned dependency in one undoable draft command. Bindings, frames and other configuration remain intact. Undo/redo and switching to an older installed version use the same draft workflow; publishing is a separate explicit action.

Distribute a ZIP with root `manifest.json` and a self-contained `.mjs` entry. Build all JavaScript dependencies into that entry; relative imports from a blob URL do not resolve. No directory ZIP members, symlinks, traversal paths, remote schema references or builtin component names are accepted. The manifest declares reverse-domain ID, semantic version, Python-compatible API specifier (for example `>=1,<2`), name, `.mjs` entry and component metadata. Components declare JSON Schemas for `property_schema` and the host `QueryResult` (`data_schema`), plus valid `default_props`. Optional metadata: `description`, `license`, `source`.

The property panel generates scalar controls from JSON Schema. Validate advanced nested configuration with the full schema before creating a package. Backend publication validates properties; runtime revalidates properties and query results before calling plugin code. Both hosts use JSON Schema Draft 7; the browser interprets schemas without `eval` or `new Function`, preserving Embed's `script-src 'self' blob:` policy. Use `definitions` and local `$ref` references. External references, newer dialects and unknown schema keywords are rejected at installation. `format`, `default`, content and read/write annotations do not add validation or mutate props. Bundle all schemas for offline use.

Installed modules are administrator-trusted same-origin JavaScript. Component error isolation is not a sandbox. Published assets require existing standalone or Embed authorization and the exact dependency in the published document. Embed retrieves code with its bearer ticket, without cookies or tokens in URLs, then imports a temporary blob module.

`definePlugin` is a typed identity helper, not a runtime validator. Run `pnpm --filter @datapulse/plugin-sdk typecheck` for its type contract; the web ecosystem tests cover actual module loading, schema checks, mount/update/destroy, migration and error isolation. There is no empty SDK test command.
